## 0. アプリの目的と最重要タスク

40〜50代男性向けの健康記録帳。**夜・風呂上がり・晩酌中・片手・暗い部屋**で使う。

| 優先 | タスク | 頻度 |
|---|---|---|
| 1 | 晩酌を1タップで加算 / 休肝日を確定 | 飲む日は一晩に数回 |
| 2 | 今日の数値(体重・腹囲・血圧・歩数・睡眠)を保存 | 1日1回 |
| 3 | いまの判定と直近の推移を見る | 1日1回・受動 |

**母艦画面 = ホーム**(このアプリは1画面構成。下部タブは同一ページ内スクロールで、別画面ではない)。

## 1. 機能一覧(実装済み・実データのみ)

### F1. 晩酌カウンター
- 4種の大ボタン(**ビール / ハイボール / 日本酒 / ワイン**)をタップすると当日の杯数を +1 して**即保存**
- 「その他のお酒」を開くと 3種追加(**缶ビール / 焼酎 / チューハイ**)
- 押した種類には杯数バッジ(`×2`)が出る
- **純アルコール量(g)に換算**して合計を表示。40g超のとき「そろそろ十分では」を添える
- 「休肝日で確定」= その日を 0g として確定。確定後は「休肝日を取り消す」に変わる
- 「やり直す」= その日の酒を未記録に戻す(押し間違い・酔った状態での誤タップ対策)
- 換算表(**変更禁止**): ビール20g / ハイボール14g / 日本酒22g / ワイン12g / 缶ビール14g / 焼酎12g / チューハイ18g

### F2. 今日の記録(日次入力)
- 入力: 日付 / 体重(kg) / 腹囲(cm) / 血圧 上・下(mmHg) / 歩数(歩) / 睡眠(時間) / メモ(自由文)
- **同じ日付に再保存するとマージ**。空欄は既存値を残す(上書きで消さない)
- 保存後に「保存しました(M/D)」を3秒表示
- 数値入力は `inputmode` 指定あり(decimal / numeric)

### F3. 今日の状態(判定)
5枚のカード。**判定は色だけでなく「帯の上のマーカー位置」で示す**(v0.1の実装方針)。

| カード | 表示 | 判定の根拠(**変更禁止**) |
|---|---|---|
| 体重 | 最新体重・前週比・BMI・目標までの差 | BMI 18.5 / 25 / 30(帯は17〜33、目盛25) |
| 腹囲 | 最新腹囲・メタボ判定・理由の一文 | **特定健診(男性)**: 腹囲85cm以上 + 追加リスク数 |
| 血圧 | 最新の上/下・区分・測定日 | **JSH2019**: 120 / 130 / 140 / 160 / 180・80 / 90 / 100 / 110 |
| 今週の酒 | 直近7日の純アルコール合計 / 140g・休肝日数 | 厚労省の目安 20g/日 × 7日 = 140g |
| 記録継続 | 連続記録日数・役職・次の役職まで | 1/3/7/14/30/60/100/365日 → 研修中〜会長 |

**メタボ判定の詳細**(`metaboClass()`):
腹囲 < 85 → セーフ / 腹囲 ≥ 85 かつ 追加リスク 0 → 腹囲オーバー / 1 → メタボ予備群 / 2以上 → メタボ該当。
追加リスク = ①血圧 130以上 または 85以上 ②中性脂肪150以上 または HDL 40未満 ③空腹時血糖110以上 または HbA1c 6.0以上(②③は健診記録がある場合のみ判定に入る)。

### F4. 30日の推移(グラフ)
- **体重**: 実測(淡い線)+ **7日移動平均**(実線・最新値ラベル)。目標体重を設定していれば点線
- **血圧**: 収縮期(実線)・拡張期(破線)・色ドット凡例・最新値ラベル
- X軸ラベルは 最初 / 中央 / 最新 の3つのみ
- 直近30日のうち**値がある日だけ**を描画(欠測日は線でつなぐ)

### F5. 健康診断(年1回の記録と経年比較)
- 7項目: γ-GTP / 中性脂肪 / HDL / LDL / 血糖 / HbA1c / 尿酸
- 表: 項目 / 今年 / 去年 / 判定。**基準を外れた数値だけ着色**
- 判定(`chkVerdict`): 要相談(基準の2段階目)/ 改善(前回比5%以上よい方向)/ 注意(基準外かつ5%以上悪化、または前回なし)/ 経過観察(基準外だが横ばい)/ 基準内
- 年表記は西暦から自動(今年/去年、離れていれば「2025年」等)
- 折りたたみのフォームから入力・上書き

### F6. ひとことコーチ / 今日の一句
- 血圧・メタボ・尿酸・γ-GTP・体重増減・休肝日ゼロの条件に当てはまるとき、**実データに基づく一文**を出す
- 該当が無ければ日替わりの健康川柳(15句・日付から決定的に選択。乱数不使用)

### F7. 健診カウントダウン(お知らせ)
- 設定した次回健診日までの残り日数と、残日数に応じた一文
- 30日以内ならヘッダーのベルに赤ドット

### F8. データ管理
- **日次CSV** 書き出し(列: `date,weight,waist,sys,dia,steps,sleep,alc_g,drinks,memo`)
- **健診CSV** 書き出し(列: `date,ggt,tg,hdl,ldl,glu,hba1c,ua`)
- **日次CSVの読み込み**(同じ日付は上書き)。BOM付きUTF-8・引用符のエスケープ対応
- 記録一覧(直近60件・削除ボタン付き)
- 設定: 身長 / 目標体重 / 次の健診日

### F9. 外殻
- 上部バー: 設定ドロワー(≡)/ アプリ名 / お知らせ(🔔・赤ドット)
- 曜日ストリップ(直近7日・記録がある日に点・今日を強調)**表示専用**
- 下部タブ4つ(ホーム / 記録 / 推移 / 健診)= 同一ページ内スクロール + 現在地表示

## 2. 実際に取得できるデータ / できないデータ

### 取得できる(すべて手入力)
体重・腹囲・血圧(上/下)・歩数・睡眠時間・メモ・飲酒(種類別の杯数)・健診7項目・身長・目標体重・次回健診日。

### 取得できない(**モックに描いても実装しない**)
| データ | 理由 |
|---|---|
| 歩数の自動取得 | ヘルスケア/Google Fit 連携なし。手入力のみ |
| 心拍・睡眠段階・SpO2 | ウェアラブル連携なし |
| 体脂肪率・筋肉量・内臓脂肪・基礎代謝・体年齢 | 体組成計連携なし。**入力欄も無い** |
| 食事・カロリー・PFC | 機能なし |
| 消費カロリー | 算出していない |
| 位置情報・天気 | 通信ゼロのため取得不能 |
| 他人との比較・ランキング・SNS | 機能なし(単独利用) |
| クラウド同期・アカウント | サーバー無し |
| 通知・リマインド | Service Worker 無し・未実装 |
| 単一の「健康スコア」 | **意図的に作らない**(根拠のない数字になるため。2026-08-18 判断) |

## 3. 画面と状態(State Matrix)

画面は1つ(ホーム)。**状態は `?state=` で再現できる**(本番URLでは無視され、この状態のときは localStorage に書き込まない)。

| 状態 | 再現 | 現在の挙動 | 検査 |
|---|---|---|---|
| 空(初回) | `?state=empty` | 各カードが「—」「未記録」+ 次にやることの一文。継続=見習い | ✅ smoke #1 / uicheck |
| 通常 | 既定 | — | ✅ |
| 長い(30日+健診2回) | `?state=demo` | グラフ・表・一覧が埋まる | ✅ uicheck |
| 成功(保存直後) | `?state=saved` | 「保存しました(M/D)」3秒 | ✅ smoke #3 |
| オフライン | 常時 | 通信しないので影響なし | ✅ smoke #12(外部通信0件) |
| 読込中 | — | **存在しない**(同期処理のみ)。作らない=嘘の状態を作らないため | — |
| 通信エラー | — | **存在しない**(通信しない) | — |
| 部分失敗 | — | 存在しない | — |
| null / 欠測 | 一部の値だけ入力 | 「—」表示・帯や判定を出さない | ✅ smoke #1,#4,#6 |
| **保存失敗**(容量超過・プライベートモード) | 未再現 | **⚠ 未実装・未検査**。例外を握り潰す可能性 | ✗ **課題** |
| 破壊的操作(削除) | 記録一覧の削除 | `confirm()` で確認 | 部分(自動テスト無し) |

## 4. Protected Zone(UI作業で触ってはいけない)

### 4.1 判定ロジックと基準値
`bpClass` / `bmiClass` / `metaboClass` / `chkVerdict` / `CHK_METRICS` / `DRINKS`(g換算)/ `alcGrams`(旧データ互換含む)/ `RANKS` / `streakDays` / 週140g。

### 4.2 保存仕様
- localStorage キー: `ojisan_health_records` / `ojisan_health_settings` / `ojisan_health_checkups`
- レコード形(UI_HANDOFF §15 参照)。`alc: {}` = 休肝日確定、`alc: null` = 未記録 の区別を壊さない
- 同日マージ(空欄は既存値温存)
- CSV の列と順序

### 4.3 制約
- **外部通信を足さない**(CDN・Webフォント・API・アイコン読込すべて禁止)
- **偽データを表示しない**(未記録は「—」)
- 医療免責の文言を消さない
- 単一ファイル・ビルド不要を維持

### 4.4 テストが掴む安定フック(変えるならテストも同時に直す)
```
#status #drinkSum #btnDry #btnSave #savedMsg #checkup #bellDot #bellPanel
#btnBell #btnMenu #drawer #scrim #btnCsvDay #fileImport
#fWeight #fWaist #fSys #fDia #fSteps
[data-drink="b500|high|sake|wine|b350|sho|chu"]
[data-go="sec-home|sec-record|sec-trend|sec-checkup"]
.tab[aria-current]
```
`?state=empty|demo|saved` の再現フックも維持する(uicheck が状態別スクショに使う)。
