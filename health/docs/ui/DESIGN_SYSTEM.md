# A層 — 不変の制約

## A1. 使う場面(これがすべての判断の根拠)

**夜・風呂上がり(手が濡れている)・晩酌中(酔っている)・暗い部屋・片手・急いでいない。**

ここから出てくる要求:
- タップ領域は**48px以上**。押し間違いを**戻せる**手段を必ず置く
- 数字は大きく。小さい文字に情報を詰めない
- **ダークモード必須**(暗い部屋で眩しくない)
- 主操作は**親指の届く下側**に置く
- ホバー前提の操作を作らない

## A2. 対象端末

360 / 390px 幅を基準に検査。コンテンツ幅は中央寄せの上限(v0.1 は 480px)。
Safe Area(`env(safe-area-inset-*)`)と `viewport-fit=cover` を必ず使う。`100vh` は使わない。

## A3. 制約(技術)

| 制約 | 理由 |
|---|---|
| **外部依存ゼロ**(CDN・Webフォント・外部アイコン・API) | オフラインで動くことが仕様。uicheck の HARD 項目 |
| **単一HTMLファイル・ビルド不要** | 配布と復旧を単純に保つ |
| 生の16進は `:root` の中だけ | 機械で数えられる(`css_raw_hex_outside_root: 0`) |
| 文字サイズは**5〜6種以内**・角丸は**3種以内** | 階層をむやみに増やさない。機械検査あり |
| 画像を使う場合は**ローカル・圧縮・license記録** | 外部CDN依存を増やさない |

## A4. Typography の方針

- **system font を使う**(`system-ui, -apple-system, "Segoe UI", "Hiragino Kaku Gothic ProN", Meiryo, sans-serif`)。ライセンス問題がなく、ネイティブ移植も容易
- Webフォントを足すなら**ローカルバンドル + license 記録 + 表示の遅延なし**が条件。安易に足さない
- 入力欄は **16px以上**(iOS の自動ズーム防止)
- 数字が縦に並ぶ場所(表・軸)は `tabular-nums`。大きな単独の数値は既定の字形でよい
- 日本語と数字が混ざるので、**字間を詰めすぎない**

## A5. 色の使い方の方針

- 状態色は **good / warn / bad の3つ**に限定し、それ以外の意味に流用しない
- **色だけで意味を伝えない**。判定は必ず語(ラベル)を伴う
- ライト・ダークは**同じ役割名(トークン)で値だけ差し替える**。セレクタを分けない
- コントラストは**全状態で不足0**を維持

## A6. 部品の言語(v0.1 で確立し、次も踏襲する候補)

新しい Reference が別の表現を採る場合は差し替えてよいが、**同じ役割の部品を2種類作らない**。

| 部品 | 役割 |
|---|---|
| カード | 1つの指標 = 1枚。アイコン+ラベル → 大きな数値 → 判定 → 理由の一文 |
| **帯マーカー** | 判定を「基準からどれだけ離れているか」の位置で示す。両端に語、基準位置に目盛 |
| ピル | 判定ラベル。枠線(面の色を増やさない) |
| メーター | 上限のある量(週の純アルコール)。上限位置に目盛、超過は色が変わる |
| 大ボタン | 晩酌カウンター。88px以上・アイコン+名前+`+1`・押した数はバッジ |
| 入力行 | ラベル / 右寄せ入力 / 単位(セルの外)の3列 |
| 主ボタン | 全幅・48px以上・1画面に主操作は1つ |
| 下タブ | ラベル付き。現在地が分かる |

## A7. Motion / Accessibility

- 派手なアニメーションを付けない(酔っている人が対象)
- `prefers-reduced-motion` を尊重する(スムーススクロールを含む)
- フォーカスリングを消さない(`:focus-visible` に見えるアウトライン)
- 画像的な要素には `aria-label`。グラフには内容を説明する `role="img"` + `aria-label`
- 状態は `aria-current` / `aria-pressed` で機械にも伝える

## A8. 禁止

- 架空データ・架空機能・fake interaction(FEATURE_INVENTORY §6・UI_ACCEPTANCE §2)
- 他社の画像・アイコンの持ち込み
- 単一の「健康スコア」
- ホバー前提・44px未満のタップ領域・入力16px未満
- グラデーション背景の上に本文を置く(コントラストを機械検査できなくなる)

## B2. 余白

`--sp1`=4 / `--sp2`=8 / `--sp3`=12 / `--sp4`=16 / `--sp5`=24 / `--sp6`=32 px。**この6段以外を使わない。**

## B3. 文字階層(5種)

| 変数 | 値 | 用途 |
|---|---|---|
| `--fs-hero` | 2rem(32px) | 各カードの主数値 |
| `--fs-title` | 1.25rem(20px) | セクション見出し・あいさつ・アプリ名 |
| `--fs-body` | 1rem(16px) | 本文・入力・ボタン |
| `--fs-label` | .875rem(14px) | ラベル・補足 |
| `--fs-cap` | .75rem(12px) | 単位・軸・キャプション・タブ |

body の line-height 1.55。

## B4. 角丸(3種)

`--r1`=2px(帯・メーター)/ `--r2`=4px(カード・入力・ボタン)/ `--r3`=999px(ピル・チップ・丸ボタン)。

## B5. 寸法

タップ最小 `--tap`=48px / 下タブ 56px / 上部バー 56px / 入力行 56px / 晩酌ボタン 88px / コンテンツ幅 480px。

## B6. 影

**使っていない**(面は 1px の罫線と明度差で分ける)。

# C. 差し替え手順(新しい Master Reference を採用するとき)

1. Reference を `health/docs/ui/reference/` に置き、`reference/README.md` に**適用範囲**を書く
2. Reference をブラウザで描画して computed 値を読み、**役割名**でトークンに落とす(生値を散らさない)
3. **B層をこの文書で書き換える**(A層は触らない)
4. `health/index.html` の `:root` を新しい値に置き換える
5. uicheck を回し、UI_ACCEPTANCE §1 の目標を満たすか確認
6. 満たさない場合、**Reference ではなくトークンの取り方を直す**(例: 判定ピルを塗りから枠線に変えて面の色数を減らす — v0.1 で実際に行った調整)
