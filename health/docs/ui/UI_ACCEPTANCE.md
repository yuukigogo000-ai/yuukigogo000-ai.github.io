## 0. 合格の決め方(権限の順序)

1. **ユーザーの見た目承認**(最終権限)
2. 第三者(ChatGPT等)の Screenshot Review
3. 機械検査(uicheck)と機能テスト(smoke)
4. Claude の自己採点 ← **単独では合格根拠にしない**

**部分完了を完了と呼ばない。** 欠けたものがあれば「未完了(理由)」と書く。

## 2. Data truth ゲート(Visual より上)

| # | 条件 |
|---|---|
| D1 | **架空データを表示しない。** 未記録は「—」または「未記録」。ダミー数値でグラフを埋めない |
| D2 | **取得できないデータを実装しない**(体脂肪率・心拍・カロリー・天気・他人との比較 等。FEATURE_INVENTORY §2 の一覧) |
| D3 | **押すと架空画面へ飛ぶ操作を作らない**(未実装なら表示しないか、押せないと分かる形に) |
| D4 | 判定の基準値を変えない(JSH2019・特定健診・純アルコールg換算・健診基準)。**変えるなら医学的根拠と発注者承認が必要** |
| D5 | 判定の下に**理由が読める**こと(「メタボ該当」だけで終わらせない) |
| D6 | 医療免責(「判定は目安です。診断は医師にご相談ください」)を消さない |
| D7 | 単一の「健康スコア」を作らない(根拠のない数字になるため) |

## 3. データ保全ゲート

| # | 条件 |
|---|---|
| P1 | localStorage キー3つを変えない(`ojisan_health_records` / `_settings` / `_checkups`) |
| P2 | レコード形を変えない。特に `alc: {}` = 休肝日確定 / `alc: null` = 未記録 の区別 |
| P3 | 旧データ互換(`drinks:n` → n×20g)を残す |
| P4 | 同日再保存はマージ(空欄で既存値を消さない) |
| P5 | CSV の列と順序を変えない。書き出し→読み込みの往復で件数と値が一致する |
| P6 | UI変更の前後で、Protected Zone の関数と保存仕様を diff して**不変を証明**する(プロトコル §23 Logic freeze proof) |

## 4. State Matrix(全部スクショに写すこと)

| 状態 | 再現 | 合格条件 |
|---|---|---|
| 空(初回) | `?state=empty` | 崩れない。**次に何をすればいいかが分かる** |
| 通常 | 既定 | — |
| 長い(30日+健診2回) | `?state=demo` | グラフ・表・一覧が破綻しない |
| 成功(保存直後) | `?state=saved` | 保存された事実が見て分かる |
| 欠測(一部の値だけ) | 手入力 | 「—」で表し、帯や判定を無理に出さない |
| オフライン | 常時 | 影響なし(通信しない) |
| **保存失敗** | 容量超過・プライベートモード | **⚠ v0.1 未対応。次のラウンドで「保存できなかった」と伝える実装が必要** |
| 破壊的操作(削除) | 記録一覧 | 誤操作防止の確認がある |

> 読込中・通信エラー・部分失敗は**このアプリには存在しない**(通信もサーバも無い)。作れば嘘の状態になるので作らない。

## 5. 実データ Stress Test(v0.1 で未実施 — 次ラウンドの必須項目)

| # | 条件 | 狙い |
|---|---|---|
| S1 | メモに最長級の日本語(全角40字以上)を入れて 360px で崩れない | 折返し・省略の方針確認 |
| S2 | 体重3桁(例 105.5)・血圧3桁/3桁(例 185/115)・歩数5桁(99,999)・純アルコール3桁 | worst-case の**実フォント幅**を測る |
| S3 | 健診7項目すべてに最大級の値 | 表の桁あふれ |
| S4 | 記録60件超(表示上限)と365件 | 一覧と描画の破綻 |
| S5 | 値が1件だけ / 2件だけのグラフ | 軸と線の退化 |
| S6 | すべて null(日付とメモだけ) | 判定の空振り |
| S7 | 360px + Safe Area(ノッチ) | 下タブと主ボタンの重なり |
| S8 | キーボード表示中に主ボタンが隠れないか | 入力の実用性 |

**意味のある情報を省略記号で隠さない方針**。隠す場合は、その情報が別の場所(表・ツールチップ)で読めること。

## 6. 人が見る観点(Screenshot Review・プロトコル §11)

同条件のスクショを Reference と並べて、**最大差3点だけ**を次の修正スコープにする。

1. First impression(一目で別物か)
2. Composition / Hierarchy(主役が主役に見えるか)
3. Density(詰まりすぎ / 薄すぎ)
4. Spacing / Typography
5. Color / Atmosphere
6. Card・surface の言語
7. Mobile usability(**親指で届くか**・片手・暗所)
8. Data truth(架空の情報が混ざっていないか)
9. Reference similarity

### 発注者に聞く3問(毎ラウンド固定)
1. 見本より劣って見えるところはありますか
2. 何をすればいいか(主操作)が迷わず分かりますか
3. 親指で届きますか

## 8. 停止条件(Diminishing Return)

**止める**: ユーザーが満足 / 大きな差が無い / 残差が1〜2px・微細なフォント調整中心 / これ以上の調整で可読性や安定性が下がりそう。
**続ける**: 一目で Reference と別物 / 主役が弱い / 階層が違う / 密度が違う / 「よくあるAI製UI」感が残る。

Reference が AI生成画像の場合、**pixel-perfect を目的にしない**。同じデザイン言語 + 実用品質を優先する。
