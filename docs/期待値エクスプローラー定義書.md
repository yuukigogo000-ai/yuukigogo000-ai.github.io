# 期待値エクスプローラー（Personal Expectation Explorer）定義書

版: v0.1（草案） / 作成日: 2026-08-16

## 1. 一文定義

**個人が「自分にできる範囲」（資金・時間・保管・スキル・法令・リスク許容度）を制約として登録し、その範囲内で実行可能な候補（仕入れ案件・行動）の期待値を計算・比較・探索できる、ブラウザ完結の個人用ツール。**

## 2. 背景と課題

- 既存ツール（`index.html`）で JAN → 楽天最安値 → 価格証拠CSV（14列）までは取得できる。
- しかし「その候補を実際に仕入れるべきか」は、価格差だけでは決まらない。売れる確率、手数料、送料、作業時間、資金拘束、保管スペース、法的制約が絡む。
- 個人は資金も時間も有限なので、**「儲かるか」ではなく「自分の制約の中で期待値が最大になるのはどれか」** を判断する道具が必要。

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| 候補（案件） | 評価対象となる1つの意思決定単位。例：ある商品を1個仕入れる、あるキャンペーンに参加する |
| 期待値（EV） | 候補を実行したときに得られる利益の確率加重平均（円）。下記の式で定義 |
| できる範囲（制約プロファイル） | 個人が事前に登録する実行可能条件の集合。資金上限・週あたり作業時間・保管容量・スキル・保有資格/許可・リスク許容度 |
| 探索 | 複数候補を制約でフィルタし、EV・EV/時間・EV/資金 などの指標でソート・比較し、パラメータを変えて感度を見る操作 |
| 総括的 | 価格差だけでなく、確率・コスト・時間・資金拘束・リスクまで含めて1つの数字に総合すること |

## 4. 数理モデル（コア定義）

### 4.1 基本式

1候補あたりの期待値：

```
EV = p_sell × (想定売価 − 販売手数料 − 発送送料) 
   + (1 − p_sell) × 残存価値
   − 仕入価格 − 仕入送料 − その他経費
```

- `p_sell`：想定期間内に売れる確率（0〜1）。初期は手入力、将来は実績から推定
- `残存価値`：売れなかった場合の処分価値（値下げ処分・自家消費・廃棄=0 など）

### 4.2 正規化指標（比較用）

| 指標 | 式 | 意味 |
|---|---|---|
| 時給換算EV | EV ÷ 総作業時間(h) | 時間が最も希少な人向け |
| 資金効率 | EV ÷ (仕入総額 × 想定回転日数/30) | 資金が最も希少な人向け（月あたり資金リターン） |
| 最悪ケース | 残存価値 − 総コスト | リスク許容度との照合に使用 |

### 4.3 判定

- **実行可**：すべての制約を満たし、EV > 0 かつ 最悪ケース ≥ −（許容損失額）
- **保留**：EV > 0 だが制約に抵触（例：資金上限超過）→ 抵触した制約を明示
- **見送り**：EV ≤ 0

## 5. 「個人のできる範囲」＝制約プロファイルの定義

ユーザーが最初に1回登録し、以後すべての候補評価に自動適用される。

| 制約 | 型 | 例 | 判定への使い方 |
|---|---|---|---|
| 運転資金上限 | 円 | 50,000円 | 仕入総額（資金拘束中の合計含む）がこれを超える候補は「保留」 |
| 1件あたり上限 | 円 | 10,000円 | 単価の高すぎる候補を除外 |
| 週あたり作業時間 | 時間 | 5h/週 | 総所要時間が残時間を超える候補は「保留」 |
| 保管容量 | 個数 or サイズ区分 | 30個まで | 在庫数の上限管理 |
| 許容損失（1件） | 円 | 3,000円 | 最悪ケースがこれを下回る候補は「見送り」 |
| 保有資格・許可 | チェックリスト | 古物商許可の有無 | 中古品の仕入候補は許可がなければ除外 |
| 取扱い禁止カテゴリ | リスト | 酒類・医薬品・チケット等 | 法令・規約上扱えないカテゴリを機械的に除外 |
| 販売チャネル | リスト | メルカリ / 楽天 / ヤフオク | 手数料率・送料テーブルの自動適用に使用 |

> 法令上の判断（古物商許可の要否、転売規制品など）はアプリは断定せず、**該当可能性の警告と自己申告チェック**に留める。

## 6. 機能要件

### 6.1 MVP（v1）

1. **制約プロファイル登録**：上表の項目を入力し、localStorage に保存
2. **候補の取り込み**：
   - 手入力フォーム（1件ずつ）
   - 既存ツールの**価格証拠テンプレート.csv（14列）を読み込み**、`price`/`source_ref`/`jan` 等を候補の下書きとして展開
3. **EV計算機**：4章の式に基づき、1候補の EV / 時給換算EV / 資金効率 / 最悪ケース を即時計算
4. **探索ビュー**：候補一覧を指標でソート・制約でフィルタし、実行可 / 保留（理由付き）/ 見送り に色分け表示
5. **感度スライダー**：`p_sell` と想定売価をスライダーで動かし、EVがどう変わるか（損益分岐となる p_sell）を表示
6. **CSVエクスポート**：評価結果一覧をCSVでダウンロード

### 6.2 将来（v2以降）

- 売却実績の記録 → `p_sell`・回転日数の実績ベース推定
- 楽天API連携による売価の自動更新（既存ツールのキー管理方式を流用）
- 資金・時間の**ポートフォリオ最適化**（制約内でEV合計が最大になる候補の組合せ提案）
- 「せどり以外」の候補タイプ（ポイ活・キャンペーン等）のテンプレート追加

## 7. 非機能要件（既存ツールの方針を踏襲）

- **静的HTML 1ファイル**、GitHub Pages 上で動作。ビルド工程・サーバー不要
- データはすべて **localStorage / ファイル入出力のみ**。外部サーバーに送信しない
- APIキーを使う場合はブラウザ内のみで保持（既存ツールと同方式）
- 日本語UI、スマホ幅対応（`max-width` レイアウト）、ライト/ダーク両対応（`color-scheme`）
- 依存ライブラリなし（Vanilla JS）

## 8. データモデル（localStorage）

```
profile: {
  capitalMax, perItemMax, hoursPerWeek, storageMax,
  maxLossPerItem, licenses: {kobutsusho: bool, ...},
  bannedCategories: [], channels: [{name, feeRate, shippingTable}]
}

candidates: [{
  id, name, jan, sourceRef,            // 価格証拠CSVから取込可
  buyPrice, buyShipping, otherCost,
  sellPrice, sellChannel, pSell, salvageValue,
  hours, turnoverDays, quantity, category, isUsed,
  createdAt, status: "候補"|"実行"|"売却済"|"見送り",
  // 計算結果（保存時に再計算）
  ev, evPerHour, capitalEfficiency, worstCase,
  verdict: "実行可"|"保留"|"見送り", blockedBy: []
}]
```

## 9. 画面構成（1ページ内タブ）

1. **設定**：制約プロファイル入力
2. **候補**：手入力フォーム＋CSV取込＋候補一覧（判定バッジ・ソート・フィルタ）
3. **詳細/感度**：1候補のEV内訳（棒グラフ的内訳）と p_sell/売価スライダー、損益分岐 p_sell 表示
4. **実績**（v2）：売却結果の記録と推定精度の確認

## 10. スコープ外（やらないこと）

- 自動購入・自動出品などの自動売買
- 各モールの規約を回避するスクレイピング
- 法令適合性の断定（警告と自己申告チェックのみ）
- 複数ユーザー・クラウド同期

## 11. 成功指標

- 候補1件の入力〜判定表示まで **1分以内**
- CSV取込で10件の候補が**ワンクリックで下書き化**される
- 「保留」判定に必ず**理由（どの制約に当たったか）**が表示される

## 12. 既存資産との関係

```
[index.html: JAN→楽天価格ツール] → 価格証拠テンプレート.csv(14列)
                                        ↓ 取込
[期待値エクスプローラー] → 制約フィルタ＋EV計算 → 実行可/保留/見送り → 結果CSV
```

既存ツールが「**価格の事実**を集める」役、本アプリが「**その事実＋自分の制約から意思決定する**」役、という分担。
