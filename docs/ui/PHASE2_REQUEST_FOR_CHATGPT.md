## ChatGPT への依頼文(ここから下をコピー)

AI UI改善マスタープロトコル v2 の **Phase 2(Visual Direction)** を行います。
**母艦画面は「俯瞰」画面**です。この1画面の、商用品質の Visual Reference を作ってください。

### アプリ

**期待値エクスプローラー** — 人生の選択肢を同じ物差しで並べて「どれに張るか」を決める個人用ツール(PWA・未公開)。

自分のリソース(資金・時間・残り活動年数・許容損失)を登録し、**転職・資格取得・積立投資の増額・独立・移住・健康習慣**といった選択肢を、3点シナリオ(悲観/中位/楽観)と割引現在価値で**円に換算して比較**する。

**目的は予測を当てることではなく、「桁と順位を間違えない」こと。**

### 使われる場面(UI 判断の根拠)

- **迷っている夜に、スマホで、片手で**開く。急いではいないが、気持ちは重い
- 何度も開いて、数字をいじって、順位が入れ替わるのを眺める道具
- 人には見せない(共有・同期の機能は無い)
- 主目的は **「選択肢どうしを見比べて、いま張るものを決める」**

### 母艦画面(俯瞰)に実在する機能 — これ以外を描かない

現状は**上部タイトルバー + 下部4タブ**(前提 / 選択肢 / 俯瞰 / 感度)。

1. **結論カード** — 「いま張るなら『資格・スキルを取る』」+「期待値 +193万円 ・ 8%の確率で元が取れる」。有望が無ければ「条件を外せば『X』」、全滅なら「いま張れるものはありません」
2. **リスク×リターンの地図**(自前 SVG 散布図)— 横軸=最悪ケース(右ほど失うものが小さい)・縦軸=期待値。原点に基準線。点は判定で**形と色を変える**(●有望 / ◆条件付き / ○見送り)。**点をタップすると詳細行が出て、該当カードへスクロールする**
3. **選択肢カード**(N枚)— 左端に判定色のレール / 組合せ用チェックボックス / 選択肢名 + ドメイン / 判定バッジ + **期待値を特大** / 最悪ケースの横バー / 3指標(最悪ケース・損益分岐・時間対効果)/ 抵触した制約の警告行
4. **並び替え**(上部バーの1ボタン。タップで循環)— 期待値 → 最悪ケースが軽い順 → 損益分岐が低い順 → 時間対効果
5. **組合せチェック** — 複数選んだときの合計期待値 + 上限に対する使用量バー3本(一時金 / 月の資金 / 月の時間)+ ✓✗ チェックリスト(本数上限 / 全部外したときの合計損失)
6. **空状態** — 「選択肢がまだありません」+ サンプル投入ボタン

**詳細な全量は `docs/ui/FEATURE_INVENTORY.md`。**

### 取得できるデータ / できないデータ

- **できる**: 選択肢名・ドメイン(7種)・初期コスト・継続コスト・投入時間・投入期間・3点シナリオ(確率/効果額/効く年数)・メモ。そこから計算した 期待値・最悪ケース・損益分岐確率・時間対効果・資金対効果・判定(有望/条件付き/見送り)
- **できない**: **一切の外部データ**(相場・統計・為替・API)。写真・アイコン素材・他ユーザーの情報・クラウド同期・通知・実績記録

→ したがって **「更新中」「オフライン」「同期しました」「読み込み中」は不要**です。**このアプリに loading 状態は存在しません。**

### 技術制約(守れないデザインは描かないでください)

- **ライト / ダーク 両対応**(片方だけの設計にしない)
- **Web フォント禁止**(CDN 不可)。端末フォント(system-ui / Hiragino / Noto Sans JP / Meiryo)のみ
- **外部アイコンライブラリ禁止**。アイコンは自前のインライン SVG
- **画像素材は現状ゼロ**。Hero に写真を使う設計にするなら**その旨を明記**してください(ライセンス確認と `assets/` 新設が必要になります)
- モバイル first。**390×844 と 360×800** で検証します。safe-area 対応必須
- タップ対象は最低 44px(実測で 0 件違反を維持しています)
- 文字階層は 5 種まで / 角丸は 3 種まで(機械検査で数えています)
- **色は判定に予約**しています(有望=緑 / 条件付き=黄 / 見送り=グレー)。装飾で色数を増やすと判定の意味が薄れます

### いまの UI の問題(発注者・実測で判明しているもの)

1. **発注者の総評=「いったん白紙」**(2026-08-20)。generic な作りで、このアプリ固有の説得力が無い
2. **エラー状態で横はみ出しが出る**(392 > 390)。内訳の金額ラベルが絶対配置で外に出る ← 実測で発見、新 UI では必ず解消
3. **並び替えが「何順か」を押すまで分からない**
4. 情報量が多く、**結論カード → 地図 → カード → 組合せ**と縦に長い。初期表示で何を見せるべきかが弱い
5. 散布図が小さく、点が密集すると読みにくい

### 経緯(重要)

このアプリの UI は**過去に2回作られ、いずれも採用に至っていません**。

- v1: PC 幅前提の比較テーブル → スマホで横スクロール・タップ44px違反16件
- v2(直近): 別プロトコルで1から作り直した(下部4タブ・結論カード・散布図)→ **「いったん白紙」**

**2回とも、Visual Reference を正本として凍結しないまま実装に入ったことが原因**でした。だから今回は、**あなたが作る Reference を凍結してから**実装します。

2. generic な「AI が作ったカード羅列」を避けてください
3. **実装済み機能と取得可能データを尊重**してください。架空機能・架空データを描かないでください
4. 画像内の文字・数値は後で仕様と照合します(**画像の数値は正本になりません**)
5. まず Visual の方向を決めてください。**コードは書かないでください**
