## A-1. 作業成果物の置き場所

`honmono/design/redesign-v4/` に置いた。

- 根拠: 既存の内部資料が `honmono/design/` にあり、`_config.yml` で配信対象から外す運用が確立している
- 対応: `_config.yml` の `exclude` に `honmono/design/redesign-v4/` を追加した(公開面には出ない)
- 注意: このリポジトリは public なので、github.com 上では読める。秘密は置いていない

## A-2. Design Authority への橋渡しは手動

自動bridge(ChatGPT へ zip を渡して返却を受け取る経路)は、この環境に存在しない。
pipeline §8 の規定どおり **Gate H3 AWAITING_CHATGPT_DESIGN** で止める。

- Google Drive は未認証で、この非対話セッションでは認証できない

## A-3. Phase 6 以降へ進んでいない理由

Design Return が無い状態で Visual を決めることは、pipeline §0 の
「Claude Code が決定してはいけないもの」に正面から違反する。
よって Phase 5〜11 は着手していない。**部分完了を完了と呼ばない。**

代わりに、Design Return が来た瞬間に動き出せるところまでを先に作った(A-6)。

## A-4. F-ID / S-ID の粒度

「利用者から見て、それが無くなったら気づく単位」を1機能とした。

- 内部のパーサ(TIFF / JPEG / PNG / WebP / BMFF)は、利用者から見ると
  「その形式を調べられる」という1機能なので、形式ごとに分けず検出内容ごとに割り当てた
- 逆に、同じ画面内でも**利用者が別々に認識するもの**(結論・根拠一覧・生メタデータ・
  次の一手・限界)は別 F-ID にした。再設計でこれらが1つに融合されると
  検査で落ちるようにするため

## A-5. 実測で判明した、既存資料の誤り(修正済み)

`honmono/design/UI_REVIEW_BRIEF.md`(2026-08-19)は
AIアカウント鑑定を「22項目のチェックリスト」と書いている。

実測: **リスク項目18件 + 信頼シグナル4件 = 合計22項目**。
「リスク22項目」ではない。Truth 側は実測値に合わせた。
(旧資料は当時の記録としてそのまま残している)

## A-6. 検証基盤を Phase 8 より前に作った

pipeline では Phase 8 が実装後だが、**先に作って現行実装に対して通した**。

- 理由1: 再設計の前に「今どこまで動いているか」の基準線が要る
- 理由2: 検査器そのものが正しいかを、既知の正しい実装で確かめられる
- 再設計でマークアップが変わっても検査器を書き直さずに済むよう、
  UIへの参照は `verify/selectors.json` 1枚に閉じ込めた。直すのはこのファイルだけ

## A-7. 画素判定(90MB)の検査方法

`verify_ui.mjs` では推論関数を差し替えて、UIの3段階(高/疑い/薄い)・進捗・失敗の
**状態だけ**を検査している。モデルそのものの正しさは検査対象ではない。

実際に90MBを落として推論まで通る経路は、既存の `tests/csp_check.mjs` が
毎回確認している(実行済み・PASS)。二重に持たない。

## A-8. 既存検査器の実行不能を直した(機能変更ではない)

`honmono/tests/verify_site.py` と `test_overflow.js` は、特定のPCの一時ディレクトリを
直書きしていて、そのフォルダが消えた時点で実行できなくなっていた。
`SITE_ROOT` 環境変数で差し替えられるようにし、ブラウザ本体の探索も
`CHROME_PATH` / `PLAYWRIGHT_BROWSERS_PATH` に対応させた。
**検査内容は1項目も変えていない**(`--selftest` 6/6・`--mutate` 32/32 で確認済み)。

## A-9. 説明書ページの横溢れを直した(デザイン判断ではない)

`/honmono/docs/` は 360px / 390px で**ページ全体が横スクロールしていた**
(用途表の1列目が `white-space: nowrap` で折り返せないため)。

- これは Design Decision ではなく、responsive 実装の不具合
- 直し方も新規に発明していない。**同じリポジトリの `report/` と `business/` が既に使っている
  `.scroll`(`overflow-x: auto`)で表を包む**という既存の手当てをそのまま適用した
- 結果: 66通り(11ページ × 3幅 × light/dark)で横溢れ0

## A-10. Design Request に現行の見た目を渡していないことの担保

「渡していないつもり」では足りないので、機械で落とすようにした。

- `verify/sanitize_bridge.py` — 内部用 Truth から、現行UIを指す語を明示的な表で落とす
- `verify/check_package.py` — 色値・CSS・構造語・画像/CSS/HTMLの混入を検査して落とす
- `--mutate` 6/6 で「本当に落ちる」ことを確認済み

`REQUIRED_COPY.json` の `verbatim` は自動検査が完全一致で見ているため、
サニタイズの対象外にしてある(1文字も加工していない)。
