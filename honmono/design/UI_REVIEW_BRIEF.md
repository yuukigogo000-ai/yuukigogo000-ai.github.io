実装: 静的サイト(HTML/CSS/JavaScript のみ・フレームワーク不使用・ビルド工程なし)。GitHub Pages で配信。

## 0. 依頼したいこと(先に結論)

**5つのページのUIを改善したい。** 特に知りたいのは次の点です。

1. トップページで「このサイトが何者で、何ができるのか」が5秒で伝わるか。伝わらないなら構成をどう変えるべきか
2. 中核ツール(画像来歴チェッカー)の**結果画面**の情報設計。いま「判定」「AI判定スコア」「検出されたシグナル」「抽出メタデータ」が縦に4カード並んでおり、素人には情報過多・玄人には物足りない可能性がある
3. **確信度を正直に伝えるUI**。このツールは「白黒をつけない」のが設計思想で、断定を避ける文言が多い。それでも使う人が行動を決められる見せ方はどうあるべきか
4. スマホでの体験(利用者の大半がスマホでSNSの画像を調べる想定)
5. 「無料の実験ツール」ではなく「信用できる検証機関」に見える見た目にするには何が足りないか

制約(守ってほしいこと):
- **人物・顔・手を描いた画像素材は一切使えない**(AI生成画像で人物を描くとこのプロジェクトの主張と矛盾するため。実写の人物写真も権利上使わない)
- 静的サイト維持(サーバー処理なし・ログイン機能なし・画像は外部送信しない)
- 追加ライブラリは原則なし(現在の外部依存は c2pa-js と onnxruntime-web の2つだけ、いずれも同梱済み)
- 日本語が主言語

## 1. このソフトの目的

### 背景
生成AIで「実在しない美女」を無限に作れるようになった結果、
- SNSには実在しない人物のアカウントが溢れ、詐欺(ロマンス詐欺・投資勧誘)の道具になっている
- 一方で**実在する人**が「その写真AIでしょ」と疑われ、証明する手段がない

### 目的
**「AI美女を作る側」に回らずに、AI美女ビジネスに対抗する。**
AI生成が増えるほど価値が上がる方向、つまり「実在すること」の証明・検出・可視化に賭ける。

設計の3本柱:
1. **証明する** — 実在の人間・実写のコンテンツであることを、来歴データと相互リンクで示す
2. **見分ける** — AI製アカウント・なりすまし・詐欺を、誰でも使える道具で検知する
3. **束ねる** — 「本物であること」を選んだクリエイターを可視化し、仕事とファンにつなぐ

### 一貫した思想(UIにも反映が必要)
- **断定しない。** メタデータは消せる/偽装できるので「痕跡なし=本物」ではない。この限界を隠さない
- **データを送信しない。** 全処理がブラウザ内で完結する。サーバーに画像は行かない(これは強い差別化要素だが、現状は文章でしか伝えられていない)
- **数字は実測のみ。** 精度は自分で測った値だけを載せ、都合の悪い数字も出す

### 2-1. トップページ `/honmono/`

現在の構成(上から順に):
1. ヘッダー: ブランド名「HONMONO」+ 5つのナビリンク(横並び)
2. **ヒーロー**: 見出し「AIが「美女」を無限に作る時代、いちばん希少なのは「本物の人間」です。」+ 説明文3行
3. **ツール一覧**: カード4枚(グリッド)。各カードは絵文字アイコン + タイトル + 説明2行 + 「→」リンク
4. **なぜ作ったか**: 説明文 + 3本柱(左に色の縦線が入った箇条書き)
5. **ロードマップ**: Phase 1(現在)/ Phase 2 / Phase 3 の箇条書き
6. **免責**: 枠付きの注意文
7. フッター: 「すべての処理はあなたのブラウザ内で完結します」

問題として認識していること:
- 画像・図が1枚もない(絵文字だけ)。文章が多く、スクロールしないと何ができるか分からない
- 「今すぐ試す」導線が弱い(いきなり画像をドロップできる入口がトップに無い)
- ロードマップと免責が、初見の人には不要な情報かもしれない

### 2-2. 画像来歴チェッカー `/honmono/checker/`(中核ツール)

**何をするか**: 画像や動画をドロップすると、その場で解析して「AI生成の痕跡があるか」「カメラで撮られた痕跡があるか」を判定材料として提示する。ファイルは外部に送信されない。

**対応形式**: JPEG / PNG / WebP / HEIC / AVIF / MP4 / MOV

**解析している内容**(すべてブラウザ内で自前実装):
- **C2PA(コンテンツ来歴)署名の検証** — Adobe/OpenAI等が画像に埋め込む電子署名。誰がいつ何のツールで作ったかを暗号学的に検証(c2pa-js を同梱)
- **EXIF / XMP / IPTC メタデータ** — カメラ機種、撮影日時、レンズ、GPS、著作権表示、生成AIツール名など
- **生成AIツールの痕跡** — Midjourney / DALL·E / Stable Diffusion / ComfyUI など30種以上のパターン、および「Generative AI」「AI generated」「生成AI」等の汎用表記
- **ストック素材サイトの痕跡** — Adobe Stock / Getty / PIXTA など16サイト
- **JPEG の圧縮特性** — 量子化テーブルから推定した品質、カメラ由来かソフト由来かの手がかり
- **サムネイル比較** — EXIF内の縮小画像と本画像を比べ、加工の痕跡を検出
- **🧪 画素からのAI判定(実験機能)** — 下記2-2-Bで詳述

**判定の種類(6段階)**: 結果は上部に大きく1つ表示される
| アイコン | 判定 | 意味 |
|---|---|---|
| 🤖 | AI生成の痕跡があります | 生成AIツール名などが見つかった |
| 📜 | コンテンツ来歴(C2PA)付きの画像です | 電子署名がある |
| 📷 | カメラ撮影の痕跡があります | カメラのEXIFがある |
| 🗂️ | ストック素材サイト由来の画像です | 素材サイトの表記がある |
| 🟡 | AI生成を疑う手がかりがあります(弱) | 生成AIでよくある画像サイズ等 |
| ❓ | 判定材料がありません | メタデータが削除されている(SNS経由の画像は大半がこれ) |

**結果画面の現在の構成**(上から縦に):
1. ファイル情報カード(プレビュー画像 + ファイル名 + サイズ/形式/寸法)
2. **判定**(上の6種類のうち1つ。大きめの色付きボックス)
3. C2PA署名の検証カード(署名がある場合のみ表示)
4. 🧪 画素からのAI判定カード(実験機能・オレンジ枠・下記)
5. 検出されたシグナルカード(見つかった手がかりの一覧)
6. 「次の一手: 逆画像検索で確かめる」カード(Google レンズ / Bing / Yandex / TinEye への4ボタン)
7. 抽出メタデータカード(表形式・XMPの生データは折りたたみ)
8. 判定の限界の注意書き

#### 2-2-B. 🧪 画素からのAI判定(実験機能)

メタデータが消された画像(SNS経由はほぼ全部これ)には上の解析が効かないため、**画像そのものをAIモデルで判定する機能**を自前で開発して搭載した。

- 自前で学習させた判定モデル(90MB)をブラウザにダウンロードして、**端末内で推論する**(画像は送信されない)
- 初回のみ90MBのダウンロード(2回目以降は端末にキャッシュ)。判定は約0.8秒/枚
- 現在のUI: 折りたたまれたカード内に「画素判定を実行する」ボタン + 「次回から自動で実行」チェックボックス → 実行するとスコア(%)+ 帯グラフ + 3段階のラベル + 注意文
- 表示は3段階: **AI生成の可能性が高い(赤)/ AI生成の疑いあり(弱)(オレンジ)/ AI生成の兆候は薄い(緑)**

**実測精度(2026-08-19時点・学習に使っていない外部データで測定)**:
| 測定 | 結果 |
|---|---|
| 545枚の混合テスト | 実写をAIと誤判定 1.8% / AI画像の検出 70% |
| 2025年世代の生成器(Seedream 4・Gemini 2.5・FLUX Pro等) | 検出 63% |
| 人物の顔615枚(専用テスト) | **実在の人の顔の誤判定 1.1% / AI生成の顔の検出 92%** |

**正直に開示している弱点**(UIにも書いてある):
- 2025年世代の生成器を約4割見逃す
- 白黒写真は検出率が15ポイント落ちる
- 古いGAN風に切り取られた顔では誤判定が5%まで上がる
- 「AIではない」証明には使えない

**UI上の課題**: 90MBのダウンロードが必要なこと、実験機能であること、確信度の意味を、狭いカード内で説明しきれていない。

### 2-3. 実在証明バッジ `/honmono/badge/`

**何をするか**: 実在するクリエイターが「自分は実在する人間です」と示すための**証明ページ(HTML)とバッジ**を生成する。審査はなく、仕組みは「相互リンク」——複数のSNSアカウントから証明ページへ、証明ページから各SNSへ相互にリンクを張ることで、第三者が検証できる状態を作る(なりすましは全アカウントを乗っ取らない限り成立しない)。

現在の画面(4ステップの縦長フォーム):
1. **情報を入力** — 活動名(必須)/ 活動ジャンル / SNS・公式リンク(1行1つ・2つ以上推奨)/ 実在の裏付けリンク(任意)/ 実在宣言(編集可能な定型文)/ 証明ページのURL(任意)→「証明ページとバッジを生成する」ボタン
2. **証明ページのプレビュー** — 生成されたページを表示 +「証明ページ(HTML)をダウンロード」ボタン
3. **バッジを設置** — HTML用スニペット / Markdown用スニペット(それぞれコピーボタン)
4. **仕上げ(重要)** — 相互リンクの張り方の説明

**UI上の課題**: 入力項目が多く、完成イメージが見えないまま長いフォームを埋めることになる。生成される証明ページ自体のデザインも簡素。

### 2-4. AIアカウント鑑定 `/honmono/aicheck/`

**何をするか**: 「このSNSアカウントの人は実在するか」を判断するための**22項目のチェックリスト**。当てはまる項目にチェックを入れるとリスクスコア(0〜100%)が出る。画像もアカウント名も送信せず、完全に自己判断の補助。

項目の例(リスク側):
- 手の指・歯・耳・髪の生え際に不自然な崩れがある
- 背景の文字・看板・ロゴが読めない、または崩れている
- ライブ配信・生の動画・雑談動画が一切ない
- 友人・家族・他人と一緒に写った写真が1枚もない
- DMで早い段階から金銭・投資・暗号資産の話が出る
- ビデオ通話・音声通話を理由をつけて断り続ける

項目ごとに重み(400〜800)が設定されており、「信頼シグナル」側の項目はスコアを減算する。

**結果表示**: リスク: 低(緑)/ 中(オレンジ)/ 高(赤)+ 助言文 +「診断結果をコピー」「結果画像を保存」ボタン

**UI上の課題**: 22項目のチェックボックスが延々と並ぶ。スマホでは相当な縦長。進捗感がなく、途中で離脱しそう。

## 3. 現在のデザインの実装状況

**共通CSS**(`honmono.css`・150行)がすべてのページに読み込まれ、CSS変数でテーマを定義。

配色(ライトモード):
```
背景 #fafaf9 / 文字 #1c1917 / 補助文字 #6b7280
カード #ffffff / 罫線 #e5e4e0
アクセント #0e7490(ティール)/ 濃いアクセント #155e75
成功 #15803d / 注意 #b45309 / 危険 #b91c1c
```
ダークモード(`prefers-color-scheme` で自動切替・手動切替ボタンは無い):
```
背景 #16181d / 文字 #e7e5e4 / カード #1f232b / アクセント #22a7c9
```

現在の見た目の特徴:
- **画像素材ゼロ**。アイコンはすべて絵文字(🔍🪪🕵️🌟📖)
- ロゴなし(テキストで「HONMONO」)
- カード = 白背景 + 1px罫線 + 角丸14px。影は使っていない
- フォント指定なし(OSのデフォルト)
- レスポンシブ対応は `max-width` と `flex-wrap` 程度。スマホ専用の作り込みは無し
- アニメーション・トランジションはホバー時の色変化程度
- OGP画像は1枚だけ自作(`og.png`)

**素材のルール(重要)**: 人物・顔・手を描いた画像は使えません(AI生成画像で人物を描くとプロジェクトの主張と矛盾するため)。抽象図形・幾何学模様・器具/レンズ等のモチーフは可。

### 同時に直した「中身」の問題(UI提案では戻さないでください)

- 説明書の「オフラインでも動作します」は**事実に反していた**ので削除(Service Worker が無い)
- 「なぜ偽造できない?」→「なぜ偽造が難しい?」+ 破れる条件を明記(断定をやめた)
- 「いかなる損害についても責任を負いません」は消費者契約法8条で**条項ごと無効**なので、「故意または重大な過失を除き」に限定
- **名鑑に並んでいた架空のクリエイター4名(葉山みお 等)を削除。**「実在」を売る名鑑で架空の人物をでっち上げるのは筋が通らないため、人名のない「掲載カードの見本」に差し替え、注意書きをカードの**上**へ移動
- AIアカウント鑑定の「結果画像を保存」の直前に、**特定個人を晒す使い方への警告**を追加

### ナビゲーションについて(いちばん相談したい点)

ヘッダーのナビは**5項目のまま**にしてあります(来歴チェッカー/実在証明バッジ/AIアカウント鑑定/実在クリエイター名鑑/説明書)。
新しい5ページはフッターとトップページからのみ辿れます。

- 実測レポートは**このプロジェクトの信頼の根拠**なので、もっと目立つべきかもしれません
- 一方で、ナビを7項目にすると 360px 幅で確実に破綻します
- **10ページをどう束ねるか(ナビの構造)を提案してほしいです**
