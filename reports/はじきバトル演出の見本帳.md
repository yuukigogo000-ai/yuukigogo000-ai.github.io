# 先行アプリの見本で、演出の格表を埋める

おはじきバトルの「演出の見本帳」とは、前回決めた5段の格表(ふつう・強い・大きい・山場・決着)の各段と各場面に、先行アプリの具体的な演出を1つずつ割り当てた表のことである。中身の芯は6つにまとまる。引っぱりから発射までは、桜井政博氏の「大きく引いて、一気に出し、余韻は長く」とマリオカートの火花の段を見本にする。当たりは、スプラトゥーンの「散る・光る・泡立つ・音」を同じ瞬間に重ねる作り方を真似る。れんさは Candy Crush とぷよぷよにならい、1つごとに音を上げ、節目だけ声と見た目を変える。ボス戦は、モンストの「ゲージ1本ごとの小さな勝利」と「致命的な攻撃にだけ出す前兆」を借りる。爆発の連鎖は、海物語の「同じ演出を大きさで格づける」やり方にする。決着は、Peggle の「最後だけ、できる限り劇的に」に従う。前回の報告と食い違った点のうち、大きいものは3つある。れんさの音は Candy Crush 型の半音ずつではなく5音階を既定にし、両方を耳で比べて決める。10れんさの「金」は、新しい色を足さず、今ある必殺色(もともと金色)の塗りで出す。離した瞬間の伸びは、0.08秒から1〜2コマに縮める。声は録音せず、端末の中で作る合成の呼びかけと画面の文字だけで始める。録音は、発注者が実機で「欲しい」と言ったときに5語まで後から足す。UI は、ウマ娘の「情報表示のルール表を先に作る」と、ヘブンバーンズレッドの「動きの規則書」を UI 発注書の §5a・§5b に入れればよい。そうすれば、このプロジェクトの決まり(見本なしで発明しない・トークンだけを使う・文字の段は5つ以内・自分で採点しない)とそのままつながる。弱点もはっきりしている。Web の制限で多くの出典が検索結果の抜粋止まりで、何秒か・どんな音かという数字は、文章ではほぼ1件も取れなかった。そのため表の数値はすべて出発点である。最後に付けた約50件の「動画で確かめる見本の一覧」をパソコンで見て、人がスマホで触って決める前提で書いている。

## 見本帳は、20行で「どの作品の、どの演出を、どの形で」を決める

先に表の読み方を決めておく。根拠の強さは前回と同じ3段階である。**強**は、開発者の発言や実物の仕組みをページ本文で確かめた例が複数あるもの、またはこのリポジトリの試作で測った数字があるもの。**中**は、本文で確かめた例が1つのもの、または検索結果の抜粋が複数そろうもの。**弱**は、抜粋1件・個人のブログ・筋道からの推論である。抜粋しか読めなかった出典には「抜粋」と添えた。「おはじきでの形」の列は、見本をこのゲームに移すための私の推論で、見本の作品がそう作っていると言っているわけではない。「格」は前回の格表の段で、0がふつう、4が決着である。長さと強さはすべて出発点で、駒の直径が25〜44ピクセルしかない360×800の画面で、見えるかどうかを実機で確かめて決める。

表を3つのまとまりで読むと、見本の性格がはっきりする。**離す前**の見本は、どれも「情報だけを正直に出し、何も遅らせない」側にそろっている。モンストは入力が向きだけで、引く長さで強さが変わらない。そのため引っぱり中の画面には、矢印と、キャラによってゲージとガイド線しか出ない([ja.wikipedia](https://ja.wikipedia.org/wiki/モンスターストライク))。おはじきは強さが3段あるので、段を見せる必要がある。そこでマリオカートの火花を借りる。火花は「いまどのくらい溜まったか」を、数字を使わず、手元を見たままで読ませる表示である。上の段ほど離したときに得をするが、攻略記事には、最上段まで溜めると外へ流れて良いラインを失うので青で十分な場面もある、と書かれている([Prima Games](https://primagames.com/eguides/mario-kart-8-deluxe-eguide/how-to-drive/drivers-manual)、抜粋)。マリオゴルフ スーパーラッシュも、ゲージの上のほうで止めると曲がるリスクが増える([Bleacher Report](https://bleacherreport.com/articles/2944956-mario-golf-super-rush-review-gameplay-videos-impressions-and-esports-appeal)、抜粋)。最強の段に「得だけれど危ない」を持たせる作りは、おはじきの3段とよく合う。画面のガラス越しにはゴムの手応えがない、という問題も残る。本物のゴムの引っぱり感を再現するコントローラを作った学生は、「ガラス越しに絵に触る」と「物に触る」は大きく違うと述べている([Game Developer](https://www.gamedeveloper.com/design/reach-out-and-touch-em-angry-birds-em-))。だから張力は、駒の沈み・震え・段の音で作るしかない。根拠として一番強いのは、桜井氏の「大げさに引いて、一気に動かす。やりすぎてよし」という原則である(本文確認)。

**離した後**の見本は、「一瞬で伝え、盤面を隠さない」にそろう。スプラトゥーンの野上氏の言葉は、1つの行為に4つの感覚を同時に重ねるという型として読める。エフェクトデザイナーの発言も同じ方向を向いている。エフェクトは「そのときに起きたことを一瞬で伝える」もので、格闘ゲームでヒットエフェクトを何も考えずに増し増しにすると「キャラが見えないから外してくれ」と言われる([ファミ通](https://www.famitsu.com/article/202604/72013))。1手に何度も当たるおはじきでは、2発目以降の当たりの光を弱めるのが筋になる。モンストのダメージは、弱点・属性・クリティカルという別々の理由で大きさが変わる。数字の見た目を変える理由が、ゲームの側にすでに用意されているのである。おはじきでも、数字の段は「強打だから」「掛け算が効いたから」のように理由と結びつけて変える。Fruit Ninja が「仕組みは3日、音と果汁の磨きに2か月」をかけた話は、どこに時間を使うかの物差しになる。一番磨くべきなのは、駒がぶつかる音とつぶれと散る粒である。

**山場と終わり**の見本は、「強い演出は条件つきで、たまにだけ」にそろう。モンストは、特別な撃破演出を条件を満たした一部の倒し方に限っている(抜粋)。SS は、演出より先に攻撃の回数と弱点の扱いを決めている(抜粋)。スマホ版で動くアニメのカットインを使っていない点は、繰り返し遊ぶ前提で見せ方を削っている、と読める(3DS版との比較からの推論)。獣神化以降の SS には「早く使う1段目と、溜めて強くする2段目」がある([ja.wikipedia](https://ja.wikipedia.org/wiki/モンスターストライク))。ただしこれはルールの変更なので、見た目の発注書では扱わない。Peggle は逆に、最後の1回にすべてを注ぐ。作者が仮の素材のつもりだった「歓喜の歌」・ユニコーン・虹を、そのまま残したほどである([PC Gamer](https://www.pcgamer.com/the-making-of-peggle/2))。勝敗の後では、Candy Crush の否定の音が2つしかない点が重要になる。できない手を指したときのエラー音と、軽い失敗音だけで、ほかはすべて褒めるための音である(同上の音の分析。開発者ではなく、音響の専門家による2013年の記事)。

食い違いのうち、どちらを採るか決める必要があったものが4つある。1つ目は**れんさの音を半音ずつ上げるか、5音階で上げるか**である。Candy Crush は、1手で消した列ごとに同じ音を半音ずつ上げ、「高揚感が積み上がる」作りで成功している([Game Developer](https://www.gamedeveloper.com/audio/why-candy-crush-saga-is-so-engaging-an-audio-breakdown))。前回の5音階案の根拠は Tetris Effect と Peggle 2 の音の分析で、どちらも聴いて分析した記事か抜粋である。根拠の強さは互角で、決め手はこのゲームの形になる。Candy Crush の1手で消える列はたいてい数列で、半音で上がっても音域はあまり広がらない。おはじきのれんさは10を超えうるし、1手の中で衝突音・強打の低音・節目の和音が重なって鳴る。半音で12段上がると、1オクターブの中で隣り合う音がぶつかる。5音階には半音の隔たりがないので、どの2音が重なっても濁りにくい(音楽の一般的な性質からの推論)。そこで**既定は5音階**にする。1れんさ目のドから10れんさ目の2つ上のラまで、ほぼ2オクターブを上り、11からは頭打ちにする。ただし `chainScale` のような切り替えを1か所に置き、実機で半音と聴き比べる。決めるのは耳である。

2つ目は**10れんさの色**である。今回のれんさの調査メモは、最上位だけ「金系」の専用色を勧めていた。前回の報告と UI 発注書は、新しい色を足さないと決めている。調べると、試作の必殺色(`--ult`)はライトで #b7791f、ダークで #f0b54a と、もともと金色だった([page.html](../prototypes/flick-battle/play/page.html))。だから、新しい色を足さずに「必殺色の地に白い文字の札」で金を出せる。両方の方針がそのまま立つ。3れんさの必殺+1と色が同じになるが、意味は「必殺に近づく大きな手」でつながっているので、混乱は小さいと見る。

3つ目は**発射の伸びの長さ**である。前回は「0.8→1.2を約0.08秒」としていた。任天堂の調査メモは、桜井氏の「時間ギリギリまで溜めた後、次の絵を一気に送る」から「伸びは1〜2コマ」を出している([ファミ通](https://www.famitsu.com/news/201904/22174831.html))。つぶれ(溜め)は引っぱっている間に済んでいるので、離した瞬間は1〜2コマで伸びきり、ばねで戻る時間(0.3〜0.4秒)を長くとる。こちらを採る。発言が本文で確かめられていて、「離して0.1秒以内に動く」という前回の決まりとも合うからである。

4つ目は**10れんさの暗転と光の範囲**である。れんさのメモは、10れんさで「暗転と画面全体の光」を出す案を書いていた。エフェクトのメモは、全画面の加算の光を避けて駒の周りに限る、としていた。ポケモンショックでは4秒間に106回の点滅があり、のちに放送の指針が、鮮やかな赤の点滅、強いコントラストの反転、急な場面転換に注意を求めた([ja.wikipedia](https://ja.wikipedia.org/wiki/ポケモンショック))。そこで、10れんさの「暗転」は背景を20〜30%暗くするだけにとどめ、白く光らせるのは駒の周りだけにする。どちらも1回だけで、繰り返さない。

## れんさは「1つごとに音、節目だけ見た目」で10段を組む

れんさの見本は、どれも同じ2つの手を使っている。1つは**回数が増えるたびに連続して上がる音**、もう1つは**節目でだけ切り替わる見た目と言葉**である。ぷよぷよの声は、初代アーケードで2〜5連鎖目の4段だったものが、『ぷよぷよ通』で1〜7連鎖目の7段になり、7連鎖で打ち止めになった([ja.wikipedia: ぷよぷよ通](https://ja.wikipedia.org/wiki/ぷよぷよ通))。台詞は数字ではなく、攻撃の魔法の名前が格上げされていく形である。大きな連鎖で声が重なる演出の元は、倍率が上がるごとに重なる回数が増える魔法「ダイアキュート」だった([ja.wikipedia: ぷよぷよ](https://ja.wikipedia.org/wiki/ぷよぷよ))。おはじきの「1つごとに×1.15の掛け算」は、この「倍率が重なる→声が重なる」とそのまま対応づけられる。太鼓の達人は判定を「良・可・不可」の3段に絞り、最上位の「フルコンボ」「ドンダフルコンボ」は曲の最後にだけ出す。イエローVer. ではコンボ数の表示が「10コンボから3コンボに変更」された(表示が始まる数と読めるが、原文の意味は確定できない)([ja.wikipedia](https://ja.wikipedia.org/wiki/太鼓の達人))。デビル メイ クライ4は評価を D〜SSS の言葉で上げ、最後の3段では Smokin'、Smokin' Style、Smokin' Sick Style と言葉自体が長くなる([Wikipedia](https://en.wikipedia.org/wiki/Devil_May_Cry_4))。ツムツムは7チェーンでボムが出て、9チェーンではマジカルボムが出ることもある。フィーバーでは画面が暗くなり、得点が3倍になる([ja.wikipedia](https://ja.wikipedia.org/wiki/ディズニー_ツムツム))。パチスロの初代北斗の拳も、10連で BGM が主題歌に変わることがあり、20連で特別な演出が出る([ja.wikipedia](https://ja.wikipedia.org/wiki/北斗の拳_%28パチスロ%29))。どの作品も、節目に「到達した」と分かる変化を置いている。

節目は、前回の報告どおりルールが変わる場所に合わせる。第2版のれんさは、1つにつき+20%で3れんさに上限(+60%)が来て、そこから1つごとに×1.15の掛け算になる。3れんさ以上の手では必殺が1つ進み、進化「大応援」は5れんさ目から効く([DESIGN.md](../prototypes/flick-battle/DESIGN.md) §5)。調整後の模擬の打ち手では、1戦の最大れんさは編成ごとの平均で3.8〜6.5、全体で約5だった([results-tune.json](../prototypes/flick-battle/engine/results-tune.json)。人が遊ぶともっと苦戦するはず、と注記がある)。つまり3と5はほぼ毎戦出て、10はまれである。だから一番大きな演出を10に置いても、すぐに飽きることはない。

この表には3つの約束を添える。1つ目は**分担**である。音と呼びかけは1つごとに連続して上げ、文字と色と画面は節目でだけ変える。文字の見た目の段は「小・中・大・特大」の4つで、画面全体の文字の5段の中に収める。2つ目は**呼びかけは1手に1回**である。呼びかけは、その手で届いた一番高い節目でだけ鳴らす。このゲームは同じ手なら必ず同じ結果になるので、離した時点で1回計算を回せば、その手の最大れんさは先に分かる。先読みを作る前の仮の形としては、節目ごとに鳴らし、1秒以内に次が来たら古いほうを止める。3つ目は**受ける側の反応**で、敵が受けたダメージの大きさに応じて、敵の反応(短い声っぽい音と、つぶれの大きさ)を2段に変える。ぷよぷよでは攻撃する側と受ける側で声が別の系統になっている(本文確認)。期待させて外す演出、本当の結果と無関係に盛る演出は入れない。

## 声は録音せず、合成の呼びかけと文字で始める

結論は「**合成音だけで作り始め、録音の声は後から5語までを任意で足す**」である。理由は5つある。1つ目に、King の音の責任者は GDC で「カジュアルゲームは約50%のプレイヤーが音を出さずに遊ぶ。毎回の操作に、音を出す理由を与えることが要る」と講演している([GDC Vault](https://gdcvault.com/play/1034493/Audio-Summit-How-Do-You))。iPhone のブラウザでは、マナーモードにすると Web の音が消える(前回の報告)。声で伝えたいことは、どのみち文字でも出さなければならない。声を足しても、増えるのは気分の部分だけである。2つ目に、駒は写真から作るシールで、種類が無限にある。1体ずつ声を録ることはできないので、キャラのつぶやきは合成しかない。節目の褒め言葉だけを録音にすると、合成のつぶやきと人の声が同じ画面で混ざり、質感がずれるおそれがある(推論)。3つ目に、声は後から足すほど保守が重い。Killer Instinct では、アナウンサーの声が変わって再録音の予定が崩れたと報じられた([Attack of the Fanboy](https://attackofthefanboy.com/news/killer-instincts-killer-audio/)、抜粋)。Candy Crush の音を分析した記事も、声には台本・声優・録音・編集・仕上げの手間がかかると挙げている([Game Developer](https://www.gamedeveloper.com/audio/why-candy-crush-saga-is-so-engaging-an-audio-breakdown))。4つ目に、段の数は少なくてよい。ぷよぷよの連鎖の声はアーケード版で4段×2人=8種類で、容量の都合で2種類まで減らした移植版もある([ja.wikipedia](https://ja.wikipedia.org/wiki/ぷよぷよ))。5つ目に、仮の画面は音源のファイルを1つも使わず、端末の中で音を作っている([ui.js](../prototypes/flick-battle/play/ui.js))。録音を入れると、オフラインで鳴らすためのファイルの事前保存と、iPhone で最初のタップに音を準備する処理が、新しい種類の素材として増える。

録音を足す利点も公平に書いておく。声は他の音より深みがあり、言葉の壁を越えて真似され、「Divine」や「Sugar Crush」のように人が口にすれば宣伝にもなる(同上の記事、本文確認)。だから、発注者が実機で触って「声が欲しい」と言ったら、3れんさは鳴らさない前提で、5れんさ・10れんさ・決着・特別版・ボスのゲージ割りの5語までを録音で足せばよい。条件は、1語0.3〜0.6秒、1手に1回、声だけを切れる設定、文字は必ず残す、権利がはっきりした声(自分で録るなど)を使う、の5つである。声・効果音・音楽を別々に切れる設定は、保存のキーが増える。見た目の発注書では保存のキーを変えない決まりなので、戦闘の差し替えの作業で扱う。

合成の呼びかけは、次の作り方が出発点になる。のこぎり波を、母音ごとの帯域の山(フォルマント)を通すフィルターに通すと、声らしさが出る。男声の目安では、「あ」が F1≈800Hz・F2≈1200Hz、「い」が F1≈300Hz・F2≈2200Hz とされる([VozCraft](https://www.mintlify.com/MateoRiosdev/Free-TTS-VozCraft/technical/audio-processing)、[pytheory](https://git.kennethreitz.org/kennethreitz/pytheory/commit/6a836dd891b10926cb46e28b3da76557c8561371)、いずれも抜粋)。子どもっぽい声にするための倍率は資料がないので、耳で決める。シールごとの声は、どうぶつの森の「どうぶつ語」と Undertale の作り方を組み合わせる。どうぶつ語のオープンソース実装は、短い音の断片をランダムな高さでつなぎ、疑問・断定・興奮で高さを上下させる([animalese](https://docs.rs/crate/animalese/0.2.0)、抜粋)。Undertale は、文字が出るたびに短い音を1つ鳴らし、キャラごとに音を変えると説明されている([分析ブログ](https://thesolarprincess.github.io/blog/en/undertaledialogue.html)、抜粋。作者本人の説明ではない)。シールには「基準の高さ・波の形・長さ・高さの揺れ幅」の4つの数だけを持たせる。喜ぶときは高さを上げ、やられたときは下げる。大きい駒は低く、小さい駒は高くすれば、耳で駒を区別できる(推論)。混ぜ方の優先順位は「声>効果音>音楽」とする講演がある([ファミ通: CEDEC 2020](https://www.famitsu.com/news/202009/04205201.html)、抜粋)。呼びかけが鳴る0.1〜0.3秒は、衝突音を少し下げる(ダッキング)。Candy Crush でも声が同時に重なって鳴る不具合が指摘されている(本文確認)。呼びかけは1本の出口に通し、新しいものが来たら古いものを止める。

## UI の決まりは、表示のルール表と動きの規則書を先に書く

上位アプリの UI について、本文で確かめられた作り方の決まりは2つに集約できる。1つはウマ娘の土肥仁氏の講演で、**画面ごとではなく「情報表示のルール」を先に作る**というものだ。情報を「洗い出し→グループ化→階層化→関連・紐づき→情報フロー」の5つの作業で整理する。育成画面は上から、ヘッダー(全体に関わる情報)、サブ情報、メイン情報、フッターの4段に分かれる。固定されるのはヘッダーとフッターで、変わるのはサブとメインである。メイン情報は「ちょうど指がくる位置」に置く。この作り方のおかげで、仕様が「毎月末にレース」から「育成目標」に変わったときも、ヘッダーに目標を足すだけで済んだ([GAME Watch](https://game.watch.impress.co.jp/docs/kikaku/1366165.html))。もう1つはヘブンバーンズレッドの長﨑二郎氏の講演で、**動きの決まりを文書にする**というものだ。単に動かすだけでは冗長になるので、「意図の伴うアニメーション」に「適切なサウンド」を付ける。品質を保つために「アニメーションコンセプト」と「アニメーションレギュレーション」という文書を作る。スマホは指が隠れ、物理的な反応がないので、押しやすい位置と大きさにし、画面を過度に明滅させない。確認は PC ではなく実機で繰り返す(PC では指が隠れる問題が再現されない)。優先度は「高・中」ではなく、全体の通し順位で管理する([4Gamer](https://www.4gamer.net/games/487/G048777/20220826055/))。

このプロジェクトの UI の決まりとは、ぶつかるところがない。ウマ娘のルール表は「トークン以外の生の値を書かない」「文字の段は5つ以内」を情報の置き方にまで広げたもので、ヘブバンの規則書は前回の格表と同じ発想である。注意点が1つある。ウマ娘はメイン情報を指の位置に置くが、おはじきでは指は引っぱるために下にあって情報を隠す。だから卓(メイン)は指より上、下の帯は空ける。これは UI 発注書(以下 WO)の §2 の判断そのままで、ヘブバンの「指が隠れる」が裏づけになる。Balatro の作者は、点数を先に見せない。見せると結果を見せる「儀式」が意味を失うからだという([GMTK](https://gmtk.substack.com/p/balatros-cursed-design-problem))。おはじきは予測線で先に見せる、逆の作りである。結果が読めるぶん驚かせる余地は小さいので、演出の重みは「順に足して最後に大きく」という儀式のほうに置く。Clash Royale の「タブの中身をすぐ出し、読み込みで待たせない」([Game Developer](https://gamedeveloper.com/audio/6-examples-of-ui-design-that-every-game-developer-should-study))も、同じ考え方につながる。

WO への組み込み方は、次の表のとおりである。

| WO の場所 | 足す・直すこと | プロジェクトの決まりとのつながり | 見本 |
|---|---|---|---|
| 新しい §5a 情報表示のルール表 | 上の帯・卓・下の帯ごとに、「何を、どの通し順位で、いつ出すか(常に・引っぱり中・長押し)、文字の段、色のトークン」を1枚の表にする。持ち物や目標が増えても、帯の中に足す・外すだけで済む形にする | トークンのみ、文字の段5つ以内 | ウマ娘(本文確認) |
| §3a 見本 | この見本帳の表を写し、動きごとに「見本・借りる点・借りない点」を記録して発注者に見せる。見本が見つからない動き(シールのめくれ・紙くず・勝ちのポーズ)は、見つかるまで今の動きのまま | 見本なしで発明しない | 本報告の見本帳 |
| §3 見本(Stitch) | 枠の部分(上の帯・必殺ボタン・勝敗の重ね表示)は Material Design 3 と Stitch で作り、卓の中の動きはゲームの見本で作る、と分担を書く | 見本なしで発明しない | 前回の報告 |
| §4 トークン | 色と同じ扱いで「動きのトークン」を置く。格表の秒・ピクセル・倍率、緩急の型(速く入ってゆっくり戻る、ばね、一定)、音の高さの段、粒の上限 | トークン以外の生の値を書かない | ヘブバン(規則書) |
| §4 文字の段 | 5段の割り当て(下の表)を書く。駒の大きさに比例する文字はやめて段に寄せる | 文字の段5つ以内 | ウマ娘、前回の報告 |
| §5b 動き | 「動きの規則書」に作り替える。1行のコンセプト(本物の結果の大きさだけ盛る。離す前は遅らせず、離した後で見せる)、格表、重なりと上限、借りない一覧を書き、各行に見本・ねらい・音の列を付ける | 見本なしで発明しない、自分で採点しない | ヘブバン(本文確認) |
| §5b 明滅 | 予告の「1.2秒周期の点滅」を「ゆっくり濃淡」に。どの演出も1秒に3回以内、赤の点滅なし | 前回の #3 | ヘブバン、ポケモンショック |
| §2 状態一覧 | 決着・ゲージ割り・カットイン・10れんさ・再生中を `?state=` で撮れるようにする | 自分で採点しない(機械で撮る) | 前回の #13 |
| §7 手順 G6 | 横並びの画像に、動きの短い画面録画と数字を添える。見本の動画は手元で見比べるだけにし、リポジトリには入れない | 自分で採点しない、他社の画像を持ち込まない | — |
| §9 受け入れ条件 AC6 | 数字を足す。1手で入力を待たせた合計(決着を除いて 0.5秒以内)、同時に出た粒の最大、最長のコマの時間、1秒あたりの明暗の変化(3回以内)、敵の番の最長 | 完了は数字で報告する | 前回の報告 |
| §1 範囲と §6 | 報酬と図鑑は別の画面なので別の WO にする。声や速さの設定は保存のキーが増えるので、戦闘の差し替えの作業へ回す | 1つの WO は1アプリ×1画面、見た目の WO で保存キーを変えない | — |

文字の段は、卓の中の文字も含めて5つにする。今の仮の画面は 9・10・11・12・13・20 ピクセルに、れんさの 16〜30 ピクセル(連続して変わる)と駒の大きさに比例する名前が混ざっていて、5段を大きく超えている。段の大きさ(ピクセル)は WO §4 でトークンとして決める。

| 段 | 使うもの |
|---|---|
| 1 特大 | 勝敗の1語、決着の特別版の言葉、10れんさの札 |
| 2 大 | 5〜9れんさ、「場外!」「ゲージを割った!」、格2以上を含む手の合計、カットインの技の名前 |
| 3 中 | 3〜4れんさ、「強打!」「巻き込んだ!」などの1語、上の帯の駒の名前、ボスのルールの1行 |
| 4 小 | ダメージの数字、予想ダメージ、倍率「×1.8」、2れんさの数字、敵のカウントの数字、格1以下の合計 |
| 5 最小 | 体力の数字、床の文字(すべる・とまる・あつい)、「落ちる」、「巻き込む」、注記 |

ヘブバンの運用からは、作る順番の決め方も借りる。優先度を「高・中」で分けず、通し順位で1列に並べる(作る順番の案は、仮の画面との対応の節の最後に書いた)。ヘブバンは、他社のモバイルゲームの UI を週2本ずつ見る会を2015年から続け、700本を超えている(同上)。おはじきでは、パソコンの作業1回につき「5作品×3画面」を見る形に落とすのが現実的である(推論)。

## エフェクトは3層・4色・寿命つきの部品で、Canvas 2D で軽く描く

2D エフェクトの作り方について、日本のエフェクト担当の言葉で本文まで確かめられたのは、サイバーコネクトツーの大塚氏の講演1件だけだった。そこから5つの原則が取れる。エフェクトは「メイン(一番見せたい必須の要素)・サブ(ないと物足りない)・賑やかし(なくても成り立つが情報量を上げる)」の3層で考える。色は多くても4階調で、近い色相に寄せる。例の爆発は、6〜7割が黄色系、2〜3割がオレンジ系、アクセントに黒系を少し、という配分である。動きにはゆっくり→速い→ゆっくりの緩急を付ける。爆発の前にエネルギーのチャージや放出を置くことがある。素材はできるだけ単純にする([4Gamer: CC2 講演](https://www.4gamer.net/games/999/G999905/20231201050/))。桜井氏も、光を足し算で重ねる描き方(加算合成)やグレアは、多用すると画面が洗練されないと語ったとされる([thetvdb の紹介ページ](https://thetvdb.plex.tv/series/masahiro-sakurai-on-creating-games/episodes/9363034)、抜粋で出典は弱い)。寿命の目安は第三者のプリセットの値しかない。閃光は約0.1秒、火の玉は約0.3秒、衝撃波の輪は約0.2秒、火花は0.5〜1秒、煙は2〜3秒で、光や火花は加算、煙や破片は通常の重ね方に向く([canvasengine](https://canvasengine.pages.dev/presets/fx)、抜粋)。プロの公式の値ではない点に注意したい。

Canvas 2D で軽く描く道具は4つある。1つ目は、ぼかし(`shadowBlur`)を毎コマ使わないこと。中心が白く外側が透明な丸い光の絵を、起動時に1回だけ裏で描いておき、毎コマは `drawImage` で貼って透明度だけを変える。`shadowBlur` を多数の図形に毎コマかけると重く([devtut](https://devtut.github.io/html/shadows/)、抜粋)、1度描いた粒を `drawImage` で貼るほうが速いという個人の実験もある([Swizec](https://swizec.com/blog/livecoding-16-canvasdrawimage-performance-is-weird-but-magical/)、抜粋)。2つ目は、粒を決まった長さの配列で使い回し、総数に上限を置くこと(出発点は同時に約200個。実機で測る)。3つ目は、1コマを2回に分けて描くこと。先に通常の重ね方で破片・煙・影・文字を描き、次に `globalCompositeOperation = 'lighter'`(加算)で光・火花・輪を描いて、最後に元へ戻す。4つ目は**ライトのテーマの扱い**である。加算は2つの層の値を足し、1を超えた分は白になる([Wikipedia: Blend modes](https://en.wikipedia.org/wiki/Blend_modes))。試作のライトの卓の色は明るい木の色(#d9c7a3)なので、加算の光は白に飽和して、ほとんど見えなくなる。ライトでは、輪や火花を通常の重ね方の濃い色に暗い縁を付けて描くよう切り替える。色は1つの効果につき「主の色・副の色・白・暗い色」の4つ以内にする。写真シールの色を使うときは、シールを作るときに1回だけ、8〜16ピクセルに縮めて平均の色を取り、駒ごとに覚えておく。毎コマ取ると重いからである(推論)。色の意味は、色だけに頼らないカラーユニバーサルデザインの考え方に従い、形と文字も併せて使う([ja.wikipedia](https://ja.wikipedia.org/wiki/カラーユニバーサルデザイン))。

|---|---|---|---|---|---|---|

演出は、敵のカウント・予告・体力の棒の上に重ねない。これらは演出より手前に描くか、演出をそこへ置かない(前回の #12)。加算の光は駒の写真の上ではなく、下か周りに描き、写真を白く飛ばさない。直近のコマの時間の平均が約20ミリ秒を超える端末では、「弱」に切り替えることを勝手にせず、知らせて選ばせる(推論)。今の仮の画面は、描画の細かさを端末の2倍までに抑えている([ui.js](../prototypes/flick-battle/play/ui.js))。粒を足しても、この上限は保つ。

## 借りないのは、結果と関係のない期待と、終わらない引き延ばし

借りない線は前回と同じである。**演出の強さが本当の結果の大きさと一致し、プレイヤーが読み取れる情報になっているなら借りる。結果より良く見せる、結果と無関係に期待を作る、止められない、のどれかに当たれば借りない。** 今回の見本帳では、上位アプリの中にも、この線の外にあるものが多く見つかった。北斗の拳の例が分かりやすい。一対一の勝負で、結果は決まっていて、見せ方が上手いから評価された。ところが同じ機種は、継続に上限も保証もない「一発大勝」の期待のために、賭博性を問題にされた([ja.wikipedia](https://ja.wikipedia.org/wiki/北斗の拳_%28パチスロ%29))。演出の巧さと射幸性は別の軸なので、前者だけを借りられる。

## 見本集めは、約50件の作業表と Game UI Database で進める

文章の資料では秒数も音も取れなかったので、次の一歩はパソコンで動画と画面を見て数えることである。見るときは観点を先に決め、一時停止とコマ送りで測る。どの作品にも共通する観点は5つある。結果が出る何秒前に何が変わるか。格の違いが色・大きさ・速さ・音のどれで表されているか。外れたときの画面は静かか。回数の節目で何が起きるか。最上位の演出が普段とどれだけ違うか。UI の画面では、さらに7つを数える。画面の下1/3に何が置かれているか。文字の段の数と大きな数の略し方。結果の出る順番と各段の秒数。ボタンを押してから反応が出るまでの時間と、沈み・縮み。長押しの説明が出る位置。NEW の印の形と消える条件。味方の順番・体力・必殺までの回数の出し方。見たものは文字のメモにして WO §3a に書く。他社の画像はリポジトリにも公開物にも入れない(CLAUDE.md の禁止事項)。

Game UI Database(gameuidatabase.com)は、画面の見本集めの土台になる。2024年8月に作り直された版には、1,341作品の5万5千枚を超える画面写真と1,700本を超える動画が入っている。画面の種類・操作・質感・模様・HUD の要素・色で絞り込め、ギャラリーにはアイコンの使い方や文字の大きさの情報も付く。色覚のフィルターがあり、無料で、作者は UI アーティストの Edd Coates である([Game Developer](https://www.gamedeveloper.com/design/game-ui-database-relaunches-with-new-features-video-support-and-over-55-000-screenshots))。使い方としては、まず作品名で探し、次に画面の種類(戦闘・結果・図鑑・チュートリアルにあたるもの)と HUD の要素(体力の棒・行動順にあたるもの)で絞る。動画は、アニメーション・画面の流れ・手触りの見本として見る。注意点が2つある。スマホの作品がどれだけ入っているかは確かめられていないし、絞り込みの実際の名前も確かめていない。載っていない作品は、動画サイトで「作品名+場面名」で探す。

## 調査の限界: 秒数と音は文章で取れず、動画で埋める

## 結論

今回分かった一番大事なことは、名作の演出が「強さ」よりも「段の数え方」で作られている点である。マリオカートは火花の色を3段だけ持つ。ぷよぷよは声を7段で止め、太鼓は判定を3段に絞り、最上位を最後に1回だけ出す。海物語は同じ泡を大きさで3段に分ける。どれも段は少なく、段の境目ははっきりしていて、最上位はめったに出ない。おはじきバトルの格表は、この型をうそのない形で持っている。そこに足りなかったのは、各段の「中身の見本」と「段を何で区別するか」だった。今回それを、形・数・音の高さで区別し、色は今のトークンのまま、という形で埋めた。

もう1つ見えたのは、上位アプリの演出のうまさと、借りてはいけない仕掛けが、同じ作品の中に並んでいることだ。モンストの SS の作り方とガチャの確定演出、北斗の一対一の勝負と上限のない継続、Clash Royale の待たせない画面と宝箱の格上げの抽選が、その例である。だから見本は作品単位ではなく、場面単位で選ぶ必要がある。この見本帳が作品名ではなく場面で並んでいるのは、そのためである。次に効くのは、新しい演出を考えることではない。約50件の作業表のうち優先 A の18件を、パソコンで秒と音に置き換えることである。そこで得た数字が、格表の出発点の値を一つずつ実測の値に変えていく。
