## 1. なぜサーバー側プロキシが必要か

| 現状(BYOK版・公開停止中) | 問題 |
|---|---|
| ブラウザから Anthropic API を直接呼ぶ。利用者本人の API キーを localStorage に保存 | 一般利用者は API キーを持っていない。キー預かりは事故時の責任が重い(公開停止の理由) |
| 課金・ログイン・回数制限が存在しない | 料金モデル(月額+回数上限)を実装する場所が無い |
| モデルは `claude-opus-5` 固定 | 採用モデル(Bedrock 上の候補)へ切り替えるには呼び出しをサーバーに置くしかない(AWS 署名鍵をブラウザに置けない) |

→ 「ブラウザ → 自前 API(東京) → Bedrock(東京)」に変え、鍵・課金・回数・悪用対策・出力検査をサーバー側に集約する。

## 2. 要件

### 2.1 機能要件(初期リリース)
- R1. メールアドレスでアカウント作成・ログイン(Cognito メール OTP。メール到達=認証)
- R2. 無料枠: 生涯3回(機能制限なし。スクショ最大6枚も体験できる)。ログイン後のみ
- R3. 有料プラン: 月1,480円(税込・総額表示)。ローンチ期間は月980円×最初の3か月 → 以後1,480円(移行日を画面と規約に明示)
- R4. 有料枠: 月150回 + 1日20回(JST)。**上限到達時は返信生成のみ停止し「次回更新日時」を表示。履歴(ブラウザ内)・設定は使える。追加枠の購入導線は出さない**
- R5. 常時「残り○回」表示。残り30回/10回で画面内通知。上限到達で生成ボタン無効化
- R6. 生成 API: 会話テキスト or スクショ(最大6枚)+ゴール/トーン/分け方/追加指示/文体サンプル → 3案+いまの状況+次の一手(本番 REPLY_SCHEMA・replies は minItems/maxItems=3)。プロフィール添削も同じ経路
- R7. 決済: Stripe Checkout(サブスク)+ Customer Portal + Webhook。カード情報はサーバーを通さない。自動更新・解約方法・通常価格移行日を特商法表記と画面に明示
- R8. 解約: Customer Portal から即時可(期間末まで利用可)
- R9. 悪用対策(初期): メール認証 + AWS WAF レート制限(IP)+ アカウント別レート制限 + 同時生成1件 + idempotency key。CAPTCHA・電話番号認証・デバイス指紋は不正が実測されるまで入れない

### 2.2 非機能要件
- N1. **AI 推論は東京リージョン内で完結**(Bedrock ap-northeast-1・retention none・呼び出しログ無効。評価アカウントで実測済み。本番アカウントでも公開前に preflight で再確認し、結果を保存)
- N2. **会話・画像・返信内容をサーバーに保存しない**。S3 も使わない(初期版)。保存するのはメタデータのみ(ユーザーID・時刻・トークン数・費用・遅延・requestId・成否・失敗種別)。ログにも本文を出さない(テストで検査)
- N3. 応答時間: 実測 平均9.5秒・最大43.6秒(Kimi・tool-use・8/31 昼)。同日夕方の確証runでは **50.9秒・51.6秒・120秒タイムアウト1件**。**次の確証run(Qwen3 VL 235B・10件→30件・temperature 0.2)で p50/p90/p95/最大・120秒タイムアウト率を計測し、§4.4 の判定表で経路を確定する**(Kimi の 07×5 は p50 5.8秒・最大 7.5秒・timeout 0 だったが不採用モデルの数字)。設計上の仮置き=Regional REST API 統合60秒・Lambda 75秒・Bedrock SDK 55秒
- N4. ペイロード: Lambda 同期リクエスト上限 6MB([Lambda quotas](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html))。API Gateway は10MBだが実際のボトルネックは Lambda。**ブラウザ側で強制**: 画像最大6枚・長辺最大1600px・JPEG/WebP 圧縮・**最終 JSON リクエスト全体 4.5MB 以下**・超過時は送信前に再圧縮・それでも超えたら明確なエラー。サーバー側でも枚数・サイズ・MIME を再検査
- N5. **出力の機械検査をサーバー側でも行う**。根拠: 確証run b2 で Kimi が tool-use でも6案を返した(TXT_SHORT_07・requestId a6499ef3…)。`minItems/maxItems` はモデルへの制約であって絶対保証ではない
- N6. 秘密(AWS 認証・Stripe 秘密鍵・Webhook 署名)はサーバー側の Secrets 管理に置き、Git・ブラウザ・ログに出さない
- N7. 可観測性: 1呼び出しごとの費用とトークンを記録し、**日次で AI 原価を集計**できること。モデル試行数(成功と別)も数える(原価上限 月180/日25 の根拠)
- N8. 月額固定費は実装後に実測するまで確定値にしない(PRICING §2: 5,000円/月を保守的に仮置き)
- N9. **未解決プレースホルダ(「○○」「〇〇」「［店名］」「〈場所〉」等)は本番表示禁止**。プロンプトで「固有名詞が不明なら『気になるお店』『最近読んだ本』など、そのまま送れる自然な一般表現に置き換える」を明記済み(prompts.ts)。サーバー検査でも検知し再生成対象にする

### 2.3 法務・表記(公開時点で必要)
- プライバシーポリシー(送信先: AWS 東京(API・認証・DB・Bedrock)・Stripe。保持: 本文は保持しない/メタデータの保持期間。第三者提供なし)
- 利用規約(自動送信禁止・出力の利用は自己責任・アカウント共有禁止・回数上限・返金方針)
- 特定商取引法に基づく表記(事業者情報・価格・自動更新・解約方法・支払時期)
- 総額表示(税込)。免税/課税の判断は税務の確認事項(PRICING §2)
- 追加枠(前払式支払手段の論点)は初期版で販売しないため対象外。導入時に専門家確認
- 採用候補(Qwen3 VL 235B)の利用規約・Bedrock の Third-party model terms の確認(未了)。Moonshot(Kimi)の規約確認は不採用により不要

## 4. 選択肢の整理(決定済みの根拠として残す)

### 4.1 サーバー基盤 → **AWS 東京(決定)**
Cloudflare Workers / Vercel+Supabase は「AI 推論以外の処理場所」の説明が増え、Bedrock 署名鍵を外部 Secrets に置く必要があるため不採用。

### 4.2 API の形 → **Regional REST API + Lambda(決定)**

| 案 | 統合タイムアウト | 判定 |
|---|---|---|
| HTTP API | 30秒固定 | 不採用(43秒の tail が通らない) |
| **Regional REST API** | 既定29秒・**上限緩和申請で延長可**(スループット上限が下がる可能性あり。初期規模では問題にならない) | **採用**。60秒で申請 |
| Lambda Function URL + CloudFront | 長い | WAF を直接付けられず CloudFront 前置が要る | 不採用 |
| 非同期ジョブ + S3 一時保存 | 制限なし | 画像を一時保存する=方針違反 | **代替案のみ**(§4.4) |

### 4.3 認証 → **Cognito メール OTP(決定)**。決済 → **Stripe Checkout + Portal + Webhook**(PRICING §2 の料率)

### 4.4 長い応答の通し方 → **条件付き(計測で確定)**

| 次の確証run(30件)の計測結果 | 経路 |
|---|---|
| p95 ≤ 55秒 **かつ** 120秒超 0件 | **60秒同期候補**(Regional REST API 統合60秒の上限緩和を申請・Lambda 75秒・Bedrock SDK 55秒) |
| p95 が 55〜110秒 | **180秒への上限緩和申請を検討**(認められなければ非同期へ) |
| 120秒超が再発 | **非同期構成へ変更**(S3 一時保存 SSE・処理後即削除・最長10分 + POST→202→ポーリング。プライバシーポリシーに一時保持を追記) |

- 計測は評価器が試行単位で記録する(`fidelity_summary.json` の `criteria.latency` = p50/p90/p95/max・`timeouts`)。本番でも同じ指標を CloudWatch に出す
- 同期案のクライアントは現行の段階表示(読み取り中→分析中→作成中)を経過時間で演出

### 4.5 回数制限 → **予約方式(決定)**

| 論点 | 決定 |
|---|---|
| 消費のタイミング | モデル呼び出し前に DynamoDB で1回分を**原子的に予約** → 正常な3案を返せたら**確定** → インフラ障害・schema違反・再生成失敗で返せなければ**返却** |
| 成功上限 | 月150・日20(JST)。有料の月は Stripe 請求期間で区切る。無料は生涯3 |
| 試行上限(原価防衛) | 成功とは別に **月180・日25 のモデル試行上限**(再生成・失敗を含む)。到達時は生成停止(返却しても増えない) |
| 同時実行 | 同一ユーザーは同時生成1件(予約が原子的に弾く) |
| 二重呼び出し | リクエストに **idempotency key**(クライアント生成 UUID)。同じ key の再送は同じ結果/状態を返す。連打・再送・画面更新で二重にモデルを呼ばない |
| 上限到達時 | 生成 API は 429 相当を返し、画面は生成ボタン無効+次回更新日時。追加枠導線なし |

### 4.6 出力の機械検査(サーバー側・決定)

| 検査 | 動作 |
|---|---|
| toolUse ブロック無し / JSON 不正 / schema 不適合 | 1回だけ再生成 → 再失敗はエラー(予約を返却) |
| replies が4件以上 | **内容検査を通った先頭3件を返す**(評価runでは引き続き違反として記録) |
| replies が3件未満 | 1回だけ再生成 → 再失敗はエラー(予約を返却) |
| bubbles が1〜3件でない / why 欠落 | 該当案を除外 → 3件未満なら上と同じ |
| スキーマ外の項目(interest_level 等) | 落とす |
| 禁止出力(脈あり度の数値・格付け・センシティブ推定・操作・自動送信 = pricing_eval の BANNED_RULES) | 該当案を除外 → 3件未満なら再生成1回 |
| **未解決プレースホルダ**(○○・〇〇・［店名］・〈場所〉等 = pricing_eval の PLACEHOLDER_RE) | 該当案を除外 → 3件未満なら再生成1回 → 再失敗はエラー。**本番に表示しない** |
| 固有名詞の根拠検査(ungrounded) | 現行どおりクライアントで警告(スクショ内文字は照合不能のため) |
| 検査の実装 | pricing_eval と**同一実装を共有パッケージ化**(二重実装しない)。本文はログにも DB にも書かない |

### 4.7 悪用対策の段階
- 初期: メール認証・AWS WAF レート制限(IP)・アカウント別 1分5回・同時1件・idempotency key・使い捨てメールドメイン拒否
- 不正実測後: CAPTCHA・電話番号認証・デバイス指紋・支払い方法の重複検知

## 5. リスク

| リスク | 影響 | 手当 |
|---|---|---|
| tool-use でも schema 逸脱(6案・実測済み) | 表示崩れ | §4.6 のサーバー検査+再生成1回+予約返却 |
| 統合タイムアウト緩和が認められない | 43秒の tail が通らない | 代替案(非同期+S3)へ。判断条件を先に固定済み |
| p95 が55秒超 | タイムアウト頻発 | 同上 |
| 6MB 超過 | 送信失敗 | ブラウザ側 4.5MB 強制+再圧縮+明確なエラー |
| 採用モデルの提供終了 | サービス停止 | モデル ID 設定化・代替モデルへの切替手順 |
| Stripe Webhook 取りこぼし | 課金済みなのに使えない | 再同期ジョブ+サポート導線 |
| 会話内容の誤保存・誤ログ | 方針違反 | 本文を保存/出力しない実装+「本文がログに現れたら落ちる」テスト |
| 予約の返却漏れ | 利用者の回数が減る | 予約に TTL(5分)。TTL 切れは自動返却 |
| 月額固定費の見積り外れ | 損益分岐が動く | 実装後1か月の実測で PRICING 更新 |
| 不安定な E2E(21e2 コピー失敗トースト) | 回帰検知の信頼低下 | **公開前に原因特定か隔離**(再実行で通っただけを恒久 PASS にしない) |

## 6. 範囲外(初期リリースでやらない)
- 追加枠の販売・従量課金・回数チケット・週課金
- 脈あり度・人物評価・感情推定
- ストリーミング応答
- S3 一時保存・非同期ジョブ(代替案として設計のみ)
- 履歴のサーバー同期
