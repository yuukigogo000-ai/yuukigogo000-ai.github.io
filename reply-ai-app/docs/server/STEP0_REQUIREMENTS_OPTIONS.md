# Replier サーバー側プロキシ化 — 工程0: 要件・制約・選択肢整理(たたき台 v0.1 / 2026-09-01)

**位置づけ**: 実装には着手しない。発注者が決める項目(§7)を切り出すための整理。数値は PRICING.md v3.1 と pricing_eval の実測を正本にし、ここで新しい数字は作らない。
**前提となる既決定**: AI = Kimi K2.5(Bedrock 東京・非ストリーミング Converse + toolConfig)= 技術第一候補 / 料金 = 月1,480円(ローンチ980円×3か月)・生涯3回無料・月150回+1日20回 / **初期リリースは追加枠の販売なし。月間上限到達後は次回更新待ち** / 脈あり度は出さない(除去済み) / 自動送信はしない。

---

## 1. なぜサーバー側プロキシが必要か(現状の問題)

| 現状(BYOK版・公開停止中) | 問題 |
|---|---|
| ブラウザから Anthropic API を直接呼ぶ。利用者本人の API キーを localStorage に保存 | 一般利用者は API キーを持っていない。キー預かりは事故時の責任が重い(公開停止の理由) |
| 課金・ログイン・回数制限が存在しない | 料金モデル(月額+回数上限)を実装する場所が無い |
| モデルは `claude-opus-5` 固定 | 採用モデル(Kimi K2.5 / Bedrock)へ切り替えるには呼び出しをサーバーに置くしかない(AWS 署名鍵をブラウザに置けない) |

→ 「ブラウザ → 自前サーバー → Bedrock」に変え、鍵・課金・回数・悪用対策をサーバー側に集約する。

## 2. 要件

### 2.1 機能要件(初期リリース)
- R1. メールアドレスでアカウント作成・ログイン(メール認証必須)
- R2. 無料枠: 生涯3回(機能制限なし。スクショ最大6枚も体験できる)
- R3. 有料プラン: 月1,480円(税込・総額表示)。ローンチ期間は月980円×最初の3か月 → 以後1,480円(移行日を画面と規約に明示)
- R4. 有料枠: 月150回 + 1日20回(JST)。**上限到達時は返信生成のみ停止し「次回更新日時」を表示。履歴・設定・過去の生成結果は閲覧可**。追加枠の購入導線は初期リリースでは出さない
- R5. 常時「残り○回」表示。残り30回/10回で通知(画面内)。150回到達で生成ボタン無効化
- R6. 生成 API: 会話テキスト or スクショ(最大6枚)+ゴール/トーン/分け方/追加指示/文体サンプル → 3案+いまの状況+次の一手(本番 REPLY_SCHEMA)。プロフィール添削 API も同じ経路
- R7. 決済: Stripe。カード情報はサーバーを通さない(Stripe Checkout / Customer Portal)。自動更新・解約方法・通常価格移行日を特商法表記と画面に明示
- R8. 解約: Customer Portal から即時可(期間末まで利用可)
- R9. 悪用対策: メール認証+アカウント/IP レート制限+CAPTCHA(電話番号認証・デバイス指紋は不正が実測されるまで入れない)

### 2.2 非機能要件
- N1. **AI 推論は東京リージョン内で完結**(Bedrock ap-northeast-1・retention none・呼び出しログ無効=評価環境で実測済み。本番アカウントでも同じ状態を preflight で確認してから公開)
- N2. **会話・画像をサーバーに保存しない**(処理後に破棄)。保存するのはメタデータのみ(ユーザーID・時刻・トークン数・費用・遅延・requestId・成否)
- N3. 応答時間: 実測 平均9.5秒・最大43.6秒(Kimi・tool-use)。**30秒を超える呼び出しが存在する前提**で経路を設計する(§4.4)
- N4. ペイロード: Lambda 同期呼び出しは 6MB 上限。スクショ6枚は**クライアント側圧縮(現行: 最大辺1400px JPEG)+サーバー側サイズ検査**が必須
- N5. 出力の機械検査をサーバー側でも行う(§4.6)。理由: 確証run b2 で **Kimi が tool-use でも6案を返した事例**(TXT_SHORT_07・requestId a6499ef3…)。スキーマは replies の件数を縛っていないため、プロンプトだけに依存すると事故る
- N6. 秘密(AWS 認証・Stripe 秘密鍵・Webhook 署名)はサーバー側の Secrets 管理に置き、Git・ブラウザ・ログに出さない
- N7. 可観測性: 1呼び出しごとの費用とトークンを記録し、**日次で AI 原価を集計**できること(価格改定・悪用検知の根拠)
- N8. 月額固定費は実装後に実測するまで確定値にしない(PRICING §2: 5,000円/月を保守的に仮置き)

### 2.3 法務・表記(公開時点で必要)
- プライバシーポリシー(送信先: AWS 東京・Stripe・認証基盤・監視。保持期間。第三者提供なし)
- 利用規約(自動送信禁止・出力の利用は自己責任・アカウント共有禁止・回数上限・返金方針)
- 特定商取引法に基づく表記(事業者情報・価格・自動更新・解約方法・支払時期)
- 総額表示(税込)。免税/課税の判断は税務の確認事項(PRICING §2)
- 追加枠(前払式支払手段の論点)は**初期リリースで販売しないため、この段階では対象外**。導入時に専門家確認
- Moonshot AI(Kimi)の利用規約・Bedrock の Third-party model terms の確認(未了)

## 3. 制約(動かせないもの)

| 制約 | 出所 | 設計への影響 |
|---|---|---|
| 非ストリーミング Converse + toolConfig | 採用構成(評価はこの形で実測) | 長い応答も一括で返る → タイムアウト設計が要る |
| Kimi の tail latency 最大43.6秒 | fidelity_tooluse_kimi 実測 | API Gateway HTTP API の統合タイムアウト30秒に収まらない |
| Lambda 同期ペイロード 6MB | AWS 公式 | 画像は圧縮+検査。6枚で 6MB を超える入力は拒否 |
| 東京リージョン内で推論 | 既決定(プライバシー方針) | 推論経路は ap-northeast-1 のみ。他リージョンへの自動フォールバックはしない |
| 追加枠なし・従量課金なし(初期) | 発注者決定 | 上限到達=停止+更新待ち。課金は月額のみ |
| Kimi の EOL 未公表 | Bedrock | モデル ID は設定値にし、Qwen3 VL へ切り替えられる形にする(乗り換え先は同評価で実証済み) |
| 静的 PWA は GitHub Pages(公開リポジトリ) | 現状 | フロントに秘密を置けない。CORS/CSP でサーバーの許可オリジンを限定 |

## 4. 選択肢の整理

### 4.1 サーバー基盤

| 案 | 内容 | 利点 | 難点 | 判定 |
|---|---|---|---|---|
| **A. AWS 東京(API Gateway/Lambda/DynamoDB)** | 評価と同じアカウント・リージョンに置く | 推論と同一リージョン・IAM ロールで Bedrock 呼び出し(鍵の配布不要)・retention none を実測済み・小規模はほぼ無料枠 | 30秒タイムアウト問題(§4.4)・AWS の学習コスト | **推奨** |
| B. Cloudflare Workers + D1/KV | エッジで軽量 | 安い・速い・CAPTCHA(Turnstile)と同居 | Bedrock 呼び出しの署名鍵を Workers Secrets に置く必要・Workers の実行場所は東京とは限らず「AI 推論以外の処理場所」の説明が複雑になる | 次点 |
| C. Vercel/Supabase(Edge Functions) | 開発が速い | 認証と DB が一体 | 実行リージョンと保存先の説明が増える・Bedrock 鍵の扱いは B と同じ | 不採用(現段階) |

### 4.2 認証

| 案 | 利点 | 難点 | 判定 |
|---|---|---|---|
| **Amazon Cognito(メール OTP / パスワードレス)** | AWS 内で完結・1万 MAU まで無料・メール認証が標準 | Hosted UI の日本語 UX が固い(自前画面+SDK で回避可) | **推奨** |
| Supabase Auth | UX が良い・マジックリンク簡単 | 別サービスにメールアドレスを保存(処理場所が増える) | 次点 |
| Clerk / Auth0 | 最も楽 | 有料枠に入りやすい・海外保存 | 不採用 |
| 自作マジックリンク | 依存ゼロ | メール到達性・セキュリティを自前で背負う | 不採用 |

### 4.3 決済・サブスク

| 項目 | 選択 | 補足 |
|---|---|---|
| 決済 | **Stripe Checkout(サブスク)+ Customer Portal + Webhook** | カード情報非通過。手数料 3.6%+Billing 0.7%(PRICING §2) |
| ローンチ価格 | Stripe の Coupon(duration=repeating・3か月)で 980円 → 4か月目から 1,480円 | 「通常価格への移行日」は Checkout 画面・メール・アプリ内に表示 |
| 税 | 総額表示 1,480円。Stripe Tax は課税事業者になった時点で検討 | |
| 状態の正本 | Stripe の Subscription 状態(Webhook で DynamoDB に写す)。アプリは DynamoDB を読む | Webhook 失敗時の再同期(手動/定期)を用意 |

### 4.4 長い応答(最大43秒)の通し方 — **設計上の分岐点**

| 案 | 内容 | 利点 | 難点 | 判定 |
|---|---|---|---|---|
| **A. 非同期ジョブ(POST→202+jobId、GET でポーリング)** | Lambda(最大15分)がジョブを処理し結果を DynamoDB(TTL 数分)に置く。クライアントは 2秒間隔で取得 | API Gateway の30秒制限を構造的に回避・現行の段階表示 UX(読み取り中→分析中→作成中)と相性が良い・再読み込みでも結果を拾える | 実装が少し増える(ジョブ表 + 2エンドポイント)。結果は短時間だけサーバーに残る(TTL で自動削除・N2 の例外として明記) | **推奨** |
| B. Lambda Function URL(CloudFront 経由) | 直接呼び出しで最長 15分 | 構造が単純 | Function URL は WAF/スロットリングが直接付かない → CloudFront 前置が必須・オリジン応答タイムアウトの引き上げ申請 | 次点 |
| C. API Gateway REST + タイムアウト引き上げ | 29秒超を申請 | 変更が最小 | 引き上げは上限あり・43秒の tail に対して余裕が薄い | 不採用 |
| D. ストリーミング | 逐次返す | 体感が速い | **採用構成(非ストリーミング)に反する**。評価をやり直す必要 | 不採用 |

### 4.5 回数制限の実装

| 論点 | 案 | 推奨 |
|---|---|---|
| 数える単位 | ①呼び出し開始時に消費 ②成功応答を返した時のみ消費 | **②**(サーバー/モデル起因の失敗で利用者の回数を減らさない)。ただし失敗の連打はレート制限で止める |
| 月の区切り | ①暦月 ②Stripe の請求期間 | **②**(更新日=回数リセット日で説明が一致する)。無料枠は生涯なので区切り無し |
| 日の区切り | JST 0時 | 表示も JST |
| 上限到達時 | 生成 API は 429 相当を返し、画面は生成ボタン無効+次回更新日時 | 追加枠導線なし(初期) |
| 実装 | DynamoDB の条件付き更新(原子的にカウント)+ TTL | 二重消費・競合を防ぐ |

### 4.6 出力の機械検査(サーバー側)

| 検査 | 動作 |
|---|---|
| toolUse ブロック無し / JSON 不正 | 1回だけ再試行 → それでも失敗なら利用者に「もう一度」を返す(回数は消費しない) |
| replies が3件でない | **3件超は先頭3件に切り詰めて返す**(6案事例への対処)。2件以下は再試行1回 → 不足のまま返し画面に注記(現行 UI の shortfallNote を流用) |
| bubbles が1〜3件でない / why 欠落 | 該当案を除外し上と同じ扱い |
| interest_level 等スキーマ外の項目 | 落とす(残さない) |
| 禁止出力(脈あり度の数値・格付け・センシティブ推定・操作・自動送信) | pricing_eval の BANNED_RULES と同じ正規表現で検査 → 該当案を除外 |
| 固有名詞の根拠検査(ungrounded) | 現行どおりクライアントで警告(スクショ内文字は照合不能のため) |
| 「○○」プレースホルダ | **新規論点**: b2 の TXT_SHORT_06 で店名を「○○」で出力(3案とも)。そのまま送れないため、画面で「○○を埋めてください」の注記か、プロンプトで「知らない店名は聞き返す/未経験の形にする」の追加が必要 → 工程1で扱う |

### 4.7 悪用対策の段階

| 段階 | 内容 |
|---|---|
| 初期 | メール認証(使い捨てドメインの拒否リスト)・アカウント別レート制限(生成: 1分5回)・IP 別(API Gateway スロットリング)・CAPTCHA(登録時と無料枠の生成時) |
| 不正実測後 | 電話番号認証・デバイス指紋・支払い方法の重複検知 |

## 5. リスク

| リスク | 影響 | 手当 |
|---|---|---|
| Kimi が tool-use でもスキーマ逸脱(6案) | 表示崩れ・信頼低下 | §4.6 のサーバー検査。スキーマに minItems/maxItems=3 を足す案は Anthropic 経路との互換を確認してから(Bedrock 経路のみなら問題なし) |
| Kimi の提供終了 | サービス停止 | モデル ID を設定化・Qwen3 VL への切替手順を運用手順に含める |
| 応答43秒の tail | 離脱 | 非同期ジョブ+段階表示・タイムアウト時は回数を消費しない |
| Stripe Webhook 取りこぼし | 課金済みなのに使えない | 再同期ジョブ+サポート導線 |
| 会話内容の誤保存 | プライバシー方針違反 | ログに本文を入れない実装+テストで検査(本文文字列がログに出たら落ちるテスト) |
| 無料枠の多重取得 | 原価流出(1人3回×1.03円=3円なので実害は小さい) | メール認証+CAPTCHA で十分。過剰投資しない |
| 月額固定費の見積り外れ | 損益分岐が動く | 実装後1か月の実測で PRICING を更新 |
