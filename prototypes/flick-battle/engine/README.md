# おはじきバトル 戦闘エンジン

ハウス・グランプリの新しい戦闘(おはじきバトル)の、ルールと物理だけを持つ部品。設計は `../DESIGN.md`。
画面・絵・保存には触らないので、ゲーム本体のどの画面からでも呼べる。

## ファイル

| ファイル | 中身 |
|---|---|
| `engine.js` | 戦闘のルールと物理。依存なし。乱数なし |
| `data.js` | 12 系統の表、敵の作り方、卓 3 種、ボス 3 種(数値は仮置き) |
| `ai.js` | おまかせ(全候補を試して最善を選ぶ)。「いっきに勝つ」とバランス確認にも使う |
| `test.mjs` | 検査。`node test.mjs`(`--mutate` で検査器自身を確認) |
| `balance.mjs` | バランス確認。`node balance.mjs [戦闘数] [boss\|mob]` |
| `../play/` | 仮の戦闘画面(`node build.mjs` で 1 ファイルに組み立て) |

## 使い方

```js
import { createBattle, shoot, step, canUlt, telegraphs } from './engine.js';
import { ally, mobBattle, bossBattle } from './data.js';

const team = [ally('kitchen'), ally('food'), ally('creature'), ally('machine')]; // 並び順 = 弾く順
const s = createBattle(mobBattle('kitchen', team, ['kitchen', 'plant', 'creature']));

// 狙う番(s.phase === 'aim')に 1 手。向きは整数、強さは 1〜3、ult は必殺で弾くか
shoot(s, { dx: 3, dy: -10, power: 2, ult: false });
// 止まるまで 1/240 秒ずつ進める。描画しながらなら 1 フレームに数回呼ぶ
while (s.phase === 'resolving') step(s);
// s.events に出来事(当たった・技が出た・落ちた・れんさ…)が溜まるので、画面側で読んで空にする
// s.phase が 'won' / 'lost' になったら終わり
```

- `telegraphs(s)` … 次の敵の番で動く敵の、攻撃の形(円・帯・線など)
- `canUlt(s)` … 今の駒が必殺を使えるか
- `shoot(s, input, { preview: true })` … 敵の番を回さずに止める(予測線用)
- `cloneState(s)` … 盤面の写し(予測線・おまかせ用)
- `hashState(s)` … 盤面のハッシュ(再現性の確認用)

## 守っている決まり

- 演算は四則と平方根だけ(三角関数なし)、時間は 1/240 秒の固定刻み、入力は整数、処理は常に id 順。
  同じ手順なら同じ結果になる。Node と Chromium では一致を確認済み。**Safari と実機の ARM では未確認。**
- 1 回の動きは最長 12 秒で打ち切る保険があるが、検査では一度も発動していない。

- `node balance.mjs`(「安全な手を選ぶが狙いがずれる人」を模した打ち手):

|---|---|---|---|

| ザコ戦(5 編成) | ±11 度 | 100% | 7.3〜11.2 |
| ボス 3 種 | ±6 度 | 100% | 9.8〜15.0 |

打ち手は盤面を全部読める強い相手なので、人が遊ぶともっと苦戦するはず。**今の数値は「理不尽に負けない」ことの確認であって、ちょうどいい難しさの確認ではない。** 手応えは人が触って決める。

## 持ち物・パッシブ・ボーナス・おまけ目標(2026-11-15 追加)

今のゲームの一覧をビルド出力から読み取り、名前はそのままで効果を新しい戦闘の言葉に置き換えた。一覧と説明文は `data.js`。

- 持ち物 20 種(`ITEMS`)とパッシブ 12 種(`PASSIVES`): `ally(lineage, { item, passives, objectId, pct })` に渡すと反映される
- 2 体ボーナス(同じ系統 2 体以上)と純血(4 体全員が同じ系統): 編成から自動で判定する。説明文は `PAIR_TEXT` / `PURE_TEXT`
- モノごとのおもさ(60 種、`OBJECT_WEIGHT_ADJ`): 系統の基準から -1 / 0 / +1
- おまけ目標: `pickGoal(seed, cfg)` で 1 つ決め、`goalMet(goal, state)` で判定する
- いっきに勝つ: `isTrivial(cfg)` が真のときに出し、`autoResolve(cfg)` で結果だけ得る(`ai.js`)
- 検査: `node test-build.mjs`(56 件)

置き換えで意味が変わったもの(今の戦闘にしかない概念だったため):
早起き時計(素早さ → 必殺に必要な回数 -1)、乾電池(スキルの待ち時間 → タッチ技の効果 +30%)、双眼鏡(狙い固定 → 予測線 2 倍)、
鉄アレイ(最初の一撃 2 倍 → おもさ +1)、応援うちわ(覚醒ゲージ → れんさの上乗せ)、虫めがね(盾持ちの敵 → はがれかけの敵)、
耳栓(気絶無効 → 敵に動かされない)、座布団(防御 → 落下で失う体力が半分)、手鏡(気絶反射 → ダメージ 30% 反射)、
身軽(素早さ → よく滑る)、堅い(防御 → 受けるダメージ -5%)、気絶に強い(→ 踏んばり: 動かされる力 -40%)。
**数値はどれも仮置きで、強すぎ・弱すぎの確認はしていない。**

## ゲーム本体に組み込むときに残っていること(ソースが要る)

1. ランの進行(マップ・ショップ・大会)から `createBattle` を呼び、勝敗を返す。今の戦闘関数と置き換える
2. 味方の作り方: 素質・進化・強化カードを `ally(lineage, { pct })` の体力・攻撃力に反映する(おもさは育てない)
3. 敵の編成: 今の編成表(系統の並びと強さ%)を `mobBattle` の引数に渡す。敵の持ち物の扱い、章末の最後の相手をボスにするかは本体の構成を見て決める
4. 保存データ: 進行中のランだけ破棄し、撮ったキャラ・フィルム・欠片は残す(発注者の決定)
5. 日替わりボス: 秒数ではなく手数とおまけ目標で採点する
6. 戦闘画面: `../play/ui.js` は灰色の箱。持ち物・パッシブ・ボーナスの表示もまだ無い。絵・音・演出は別作業
7. おまかせは重い(遅い端末の模擬で 1 手 0.3〜1.5 秒、その間画面が止まる)。別スレッドに移すか候補を減らす
8. ショップ・報酬・図鑑などに出ている持ち物とパッシブの説明文を、新しい文に差し替える
