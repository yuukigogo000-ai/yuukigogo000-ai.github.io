## 1. 発注者が決めたこと(変えない)

- いまのオートバトルは捨てて、おはじきバトルに差し替える
- 必殺技は各キャラに 1 つ。おもさは 5 段階。数字は体力と攻撃力だけ
- 差し替えは「遊べるところまで」。見た目の仕上げは UI の発注書で別に進める
- 保存データは、進行中のランだけ捨てる。撮ったキャラ・フィルム・欠片は残す
- 公開はしない(main へ入れるのは、いつもの公開前の工程を通してから)

## 3. 探すときの手がかり(公開ビルドから読み取った名前。ソースでは別名のはず)

- いまの戦闘は 1 つの関数に集約されている。定数に `timeLimitTicks: 400` `fatigueStartTicks: 250` `gaugeRate: 55000` がある
- 再生の画面は「結果へ」「×1 / ×2 / ×4」のボタンを持つ。開始時に戦闘関数を 1 回呼んで、結果を再生しているだけ
- ランの進行は `tourneyMatches`(大会の試合数 2 / 3 / 3)、`lives: 5`、`mainSlotsFrom: 2` の近く
- **注意:** ここの手がかりは 11/13 の公開版から読んだもの。11/14 に UI を見本から作り直した更新(`7c72c9c` / `f230f58`)が入っているので、画面の文言(「結果へ」「×1 / ×2 / ×4」など)は変わっているかもしれない。手がかりより実際のソースを優先する。戦闘の定数(`timeLimitTicks` など)は 11/14 版にも残っていることを確認した
- 方針は `rush / guard / big`、狙いは `front / weak / strong`
- 持ち物 20 種とパッシブ 12 種のキー名は、エンジンの `data.js` と同じ(`blade` `clock` … / `sturdy` `strong` …)
- モノ 60 種のキー名も同じ(`pot` `pan` … `sponge`)

## 4. 決めておいた対応づけ(本体を見て合わなければ変えてよい。変えたら `WORKLOG` に書く)

| 本体のもの | 新しい戦闘での扱い |
|---|---|
| 並び(前から 1〜4) | 弾く順番。最初の置き場所はエンジンの既定(自陣の 4 か所) |
| 素質・進化段階・強化カード・ショップの「強化」 | まとめて `pct`(体力と攻撃力の伸び)に入れる |
| 気質(猛・堅・奇) | 猛 = 攻撃力 +6%、堅 = 体力 +6%、奇 = なし(`atkMul` / `hpMul` で渡す) |
| 攻め / 守りの分岐 | 攻め = 攻撃力 +10%、守り = 体力 +10% |
| 持ち物・パッシブ | キー名をそのまま `item` / `passives` に渡す |
| 敵の強さ% | `mobBattle(..., { pct })` |
| 敵の持ち物 | 最初は付けない(数値で代える)。後で必要なら足す |
| 出場 3 体 / 4 体 | そのまま(エンジンは 1〜4 体で動く) |
| 命 5・負けても先へ進む | そのまま |
| 引き分け | なくなる(必ず勝ちか負け) |
| 日替わりボス | `bossBattle(kind, team)` を日付で 3 体から選ぶ |

## 6. 気をつけること

- 撮影・画像認識・図鑑・フィルム・欠片には触らない
- エンジンの中で三角関数や `Math.random` を使わない(同じ手順なら同じ結果、を守るため。検査が落ちる)
- 数値(敵の体力、ボスのゲージ、持ち物の効き)はすべて仮置き。模擬の打ち手でしか確かめていないので、**発注者が触ってから調整する**
- iPhone(Safari)で同じ結果になるかは未確認。日替わりボスで成績を突き合わせないなら、後回しでよい
- `photo-roguelike/`(公開側のフォルダ)を直接編集しない。ソース側でビルドして `scripts/publish_site.mjs` で写す、といういつもの手順を守る
