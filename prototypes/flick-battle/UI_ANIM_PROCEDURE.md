## フェーズ 1(前提): 戦闘の差し替え

`HANDOFF.md` §2 の表どおり。この手順書で足すことだけ書く。

1. エンジン 3 ファイルに加え、**演出の部品 `fx/` の 7 つ**(`tokens.js` `script.js` `director.js` `audio.js` `render.js` `scenes.js` `scenes-inputs.js`)をソースに置く。どれも ES モジュールで、画面の仕組み(React)に依存しない。置き場所の例: `src/battle/engine/`・`src/battle/fx/`
2. 戦闘画面のコンポーネントは `play/ui.js` を見本にする。核は 4 つの関数:
   - `startShot(st, input)`: 離した瞬間に `scriptShot` → `planShot` で指示表を作る(`memory` は戦闘ごとに持つ)
   - `runCue(c, now)`: 指示を 1 つ実行する(止め・間・揺れ・文字・音・粒・駒の変形・暗転・スロー・寄り)
   - `frame(now)`: 本物の盤面を `step` で 1 刻みずつ進め、同じ刻みの指示を実行する。先に `pre`(敵の溜め)を実行する
   - `drawBody` / `drawInfo`: 駒の体(変形あり)と、情報(体力・カウント・予想ダメージ)を分けて描く。情報は演出より手前
   - React では canvas を `useRef` で持ち、`requestAnimationFrame` のループは `useEffect` の中に閉じる。盤面は React の state に入れない(毎コマ描き直すため)
3. 本体の盤面には `s.fx` を立てない(台本の複製の中だけで立つ)。予測線・おまかせの複製にも立てない
4. **音**: `createAudio()` を戦闘画面で 1 つ作り、**「出撃」などのタップの中で `unlock()`** を呼ぶ(iPhone は最初のタップの中で準備しないと鳴らない)。画面を開いた直後に `prepare()` を呼んでおくと、最初の 1 音で止まらない
5. **予想ダメージ**: 狙う番の間、エンジンの `threatPreview(state)` を 1 回計算して(盤面が変わるまで使い回す)、範囲の中の味方の上に出す
6. **撮影台のフック**を本体にも入れる(URL に付けたときだけ働く。本番の動作は変えない): `?scene=<場面>`・`?clock=manual`・`?state=<状態>`、`window.__fx`(`fire` `advance` `metrics` `textLog` `lum` `fxstate`)。名前と動きは `play/ui.js` の「撮影台のためのフック」の節と同じにする
7. 「演出の強さ」(標準・弱・なし)を設定に入れるかは、**保存キーが増えるので、この差し替えの作業で決める**(見た目の工程では足せない)。入れるなら OS の「動きを減らす」で既定を「弱」にする
8. テストをソースに移す: `engine/test.mjs --mutate`(123 件・6/6)、`engine/test-build.mjs`(81 件)、`fx/test.mjs --mutate`(40 件・7/7)、`fx/audio-check.mjs --mutate`(4/4)。import のパスだけ直す

**終わりの条件**: 1 ランを最初から最後まで遊べる / 上のテストがソース側で緑 / 本体の既存テストが緑 / WORKLOG を更新してコミット(作業ブランチ)。

## フェーズ 5 — G3 トークン

1. **色**: 本体の今のトークンだけを使う(新しい色を足さない)。演出の色の役割(`fx/tokens.js` の `color`)を本体のトークンに対応づけて、WO §4 に表で書く。Claude の案:

   | 演出の役割 | 仮の画面 | 本体のトークン(案) | 注意 |
   |---|---|---|---|
   | good(手柄) | `--accent` | `--green-hi` か `--green-line` | 暗いガラスの上で読めること |
   | great(山場・10 れんさの札・必殺) | `--ult` | `--gold` | 札の文字は暗い色(`--glass-2` など)で |
   | harm(危険: 自分に悪いことだけ) | `--danger` | `--red` | 敵の駒の色 `--enemy` と見分けられること |
   | plain(敵に与えた数字・合計) | `--fg` | `--ink` | — |
   | 味方 / 敵 / ボスの駒 | `--ally` `--enemy` `--boss` | 写真シール+縁の色。敵は `--enemy` | 色だけに頼らない(味方は太い縁、敵は数字の丸) |

   `fx/render.js` は canvas に描くので、CSS の変数を読んで `R.setColors(colors, isDark, font)` に渡す(`play/ui.js` の `readColors` と同じ)。本体は暗い見た目なので `isDark = true` 固定でよい(光は加算で描かれる)
2. **文字の 5 段**: 画面全体で 5 つまで。**DOM の文字(uicheck が測る)と canvas の文字(fx-check が測る)を合わせて 5 つ**にする。決めた 5 つの大きさを `fx/tokens.js` の `text.sizes` に入れ、本体の CSS の文字トークンと同じ値にする(今の仮の値は 28・20・15・12・10px)。本体の公開ビルドは今 29 種類の font-size を持つが、戦闘画面だけで 5 つにする
3. **角丸 3 つ**: 駒は円(full)、ボタン、卓の角。本体の `--r-btn` `--r-panel`(10px)を使う
4. **動き**: 枠の UI(上の帯・必殺ボタン・「…」・勝敗の重ね表示の出入り)は M3 の動きのトークン(`fx/tokens.js` の `m3`: 長さ・緩急・ばね)だけ。卓の中の動きは `fx/tokens.js` の格表・`body`・`parts`(値はそのまま。実機と見本で直すときは tokens.js だけを直す)
5. 生の値をコードに新しく書かない(CSS も canvas も)

**終わりの条件**: WO §4 が埋まり、`fx/tokens.js` の `text.sizes` と色の対応が本体と一致している。

## フェーズ 6 — G4 実装

**順番**: 枠の UI → 卓の情報 → 卓の中の演出の確認。1 領域ずつ、見返し記録 (d) を書きながら。

1. **上の帯(1 行)**: いま弾く駒の名前と必殺まで、次の 3 体を小さく、右端に「…」。中身は WO §5a の表の「上の帯」の行どおり
2. **下 1/3**: ふだんは空き。必殺が溜まったら幅いっぱいの必殺ボタン(高さ 56)。押すと構えた状態+カットイン(`R.cutin`。仮の画面に実装済み)。もう一度押すと戻る
3. **「…」**: おまかせ・きろく・やめる・設定。**おまかせは戦闘中の画面で選ぶ**(発注者の決定)。「オート戦闘」はこの画面に置かない(戦闘前の画面。別 WO)
4. **卓の情報**: 体力の棒と半分の目印、敵の数字の丸、予告の範囲(点滅しない濃淡)、予想ダメージ、ボスのゲージとルールの 1 行。**情報は演出より手前に描く**
5. **引っぱり中の表示**: 「強さ 中」は親指の下にならないよう、駒のそばか上の帯へ(WO §5-5)
6. **勝敗の重ね表示**: 1 語(段 1)→ 主の数字 1 つ → 手数・最大れんさ・おまけ目標 → 「次へ」と「決め手を再生」。1 秒以内に操作できる。負けでは祝う色と音を使わない、「もう一回」を点滅させない
7. **卓の中の演出**: 部品は仮の画面と同じものが入っている。本体の駒は写真シールなので、`drawBody` の円の塗りを写真の描画(円で切り抜いた画像)に替える。**撃破の片も写真を切った片にする**(`fx/render.js` の `ghost` の `shard` に画像を渡す改修。割れ方は見本を見てから)
8. **WO §6 の A/B** を発注者に聞く(まとめて 1 回。残りは 8 件: おまかせの場所・早送り・体力の数字・予想ダメージ・おもさ表示・持ち物・おまけ目標・先告知のランプ)
9. ロジック・保存形式・localStorage キーは変えない(見た目の工程の禁止事項)。どうしても要るものはフェーズ 1 の作業に戻して行う

**終わりの条件**: 全状態が動き、`?state=` で 14 状態すべてが撮れる。
