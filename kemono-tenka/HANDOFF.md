# 引き継ぎ書: けもの天下の物語を「物語工房」で作り直す

PC の Claude Code(物語工房が使えるセッション)向け。
クラウドのセッションからは物語工房が見えなかった(リポジトリ・スキル・GitHub のコード検索・PC の共有フォルダを探して、どこにも無かった)。
そのため、いま入っている物語は Claude が物語工房を通さずに直接書いた **仮の文** で、発注者の指示を満たしていない。

## 0. 発注者の指示(そのまま)

- 「けもの天下は題材ホラーにして。シナリオライツシステムつかって」
- 「物語工房だ」(シナリオライツシステム = 物語工房)
- 「物語工房使えなきゃだめよ。PCでやるから引き継ぎ書いて」

つまり完了の条件は **「物語工房を通して作った物語が、ゲームに入っていること」**。仮の文を手で直すだけでは完了にならない。

## 2. いまの状態

- **できている(変えなくてよい):** ルール、相手の家の考え方、画面、保存、オフライン対応、検査。
  題材を替えたときも決まりと数字は変えていない(呼び名だけ替えた)
- **仮(物語工房で作り直す対象):**
  1. 世界の設定: 「朝が来なくなった山里で、4 つのけものの家が 12 の里の灯を取り合う」
  2. 名前: 家 4 つ(鬼熊家・沼主家・妖狐家・白兎家)、里 12、憑きもの 12 人、用語(灯・もののけ・結界・百鬼夜行・夜の主 など)
  3. 夜語りの文: 始まり 4・月の語り 5(それぞれ 3 通り)・出来事の場面 11・結末 5
  4. 選ぶ出来事 14 種の文(題・本文・選択肢 2 つ・結果)
- 怖さの向きは Claude が「和風の怪談・静かで不穏・血や痛みの描写なし」と仮に決めた。**発注者はこれを承認していない。** 物語工房で決め直してよい

## 4. 入れ方

### 文だけを替える場合(いちばん小さい変更)

- 夜語り: `src/story.js` の `PROLOGUE` / `CHAPTERS` / `TRIGGERS` / `ending()` の `title` と `lines` を差し替える。`id` と `when`(出る条件)は変えない
- 選ぶ出来事: `src/core.js` の `EVENTS` の文を差し替える。効果の数字と条件は変えない
- 文の中で家の名前を出すときは、文字で書かずに `myName(s)`(自分の家)・`strongest(s).name`(いちばん強い相手)を使う

### 名前や用語も替える場合

- 家: `src/core.js` の `CLANS`。里: `PROV_DEFS`。憑きもの: `OFFICERS`。月の満ち欠け: `SEASONS`
- 用語(灯・もののけ・結界 など)は `src/core.js`(記録の文、命令できない理由の文)と `src/ui.js`(ボタン、説明)と `src/page.html` に散らばっている。
  替えるときは 3 つのファイルをまとめて検索して置きかえる
- **文字が替わると落ちる検査がある。** 替えたら合わせて直す:
  - `test.mjs`: `'6 つの月'`(時間切れの理由の文)、`'取りやめ'`
  - `balance.mjs`: `'6 つの月'`、`'百鬼夜行を組んだ'`
  - `browser-check.mjs`: ボタンの文字 `'はじめる'` `'呼び寄せ'` `'全軍'` `'やめる'` `'もう一回'` `'つづきから'`
- ゲーム名「けもの天下」と保存キー `kemono-tenka.v1` は、発注者に聞かずに変えない(名前を変えるなら候補を出して選んでもらう)

### 物語工房の出力が、いまの枠に合わない場合

枠のほうを変えてよい(物語工房を使うことが条件なので、仕組みを物語工房に合わせる)。
`story.js` が外に出しているのは次の 3 つだけなので、この形を守れば中は作り直して構わない。

- `storyDue(s)` … いま語る場面を最大 2 つ返す(`{ id, title, lines }` の配列)。語った場面の `id` を `s.story.seen` に足す
- `ending(s)` … 決着したときの結末を 1 つ返す(`{ id, title, lines }`)
- `STORY_COUNTS` … 場面の数(検査が見る)

枠の数や条件を変えたら、`test.mjs` の「夜語り」の節(16 件)を新しい数と条件に合わせて直す。検査を消して通すのは不可。

## 5. 守ること

- **決まりと数字は変えない。** 物語のために効果を変えたくなったら、発注者に聞く(既存仕様の変更にあたる)
- 1 場面は 360×800 の画面に収まる長さ。いまの目安は「題 + 4 行、1 行は全角 45 字くらいまで」。長い結末は下へ送れるが、始まりの語りは 1 画面に収める
- 1 回の遊びで語りが入る回数は、いま 4〜13 回。増やしすぎると遊びの流れが止まる(まだ人では確かめていない)
- 同じ場面を 1 回の遊びで二度語らない、1 度に語るのは 2 つまで、という決まりは検査が見ている
- `main` へ push しない(= 公開になる)。作業ブランチだけ。PR は発注者に言われたら作る
- このリポジトリは public。物語工房の中身(手順書・秘密にしたい設定)をここに写さない。入れるのは出来上がった文だけ
- 自己採点しない。文が怖いか・読みたくなるかは、発注者に読んでもらって決める

## 6. 確認コマンド

```
cd kemono-tenka
node test.mjs --mutate          # いま 85 件合格。自己検査 3 件中 3 件検出
node balance.mjs 200            # 決まりを変えていなければ、勝率は README の表と同じになる
node build.mjs                  # index.html と artifact.html を作る
NODE_PATH=$(npm root -g) node browser-check.mjs   # Git Bash では MSYS_NO_PATHCONV=1 を付ける
```

触れる版の更新: `kemono-tenka/artifact.html` を Artifact として公開する。
別の会話から更新するときは、上の URL を `url` に渡す(渡さないと別の URL になる)。

## 7. クラウド側が分かっていないこと

- 物語工房がどんな工程・出力の形を持つか(だからこの引き継ぎ書は、枠の側だけを説明している)
- 発注者が思い描いている怖さの向き(怪談寄りか、もっと強い恐怖か)
- 仮の文が、発注者の目から見て使えるところがあるか
