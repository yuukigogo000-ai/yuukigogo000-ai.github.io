## 5. デザイン仕様(実装した内容)

- **上部**: `.sl-head` = セトリ名の select(枠なし・太字)+ 右に ⋯(44×44)。それ以外のボタンは置かない

- **分析**: エナジーフロー・セトリ診断・持ち替えプランナーは曲リストの下へ移動(機能は削らない)

### 見送り事項・確認したいこと
1. **既存の不具合を発見(今回は直していない)**: `navigator.share` がある環境(デスクトップ Chromium・Electron 版)で「共有リンク」を押すと `navigator.share()` が解決せず**無反応のまま止まる**。実測で確認。見た目WOの範囲外(ロジック)なので未修正。テストは Web Share API を無効化して経路を固定した(検査内容は不変)。→ 別WOで修正するか要判断
2. **残り時間の色**: 見本はアクセント色。実装は現状どおり「余裕=緑 / 超過=赤」を維持(意味を持つ色のため)。見本に合わせるか要判断
3. **css_font_size_decl_distinct が目標未達**(13 > 8): 内訳は画面用トークン6種 + 印刷用 pt 7種。印刷用は画面に出ないため、AC3 の目標定義を「画面の実測 distinct_font_sizes ≤6」に一本化するのが妥当(数字は隠さず記載)
4. **テストの操作経路を更新**(検査内容は不変): セトリ操作は ⋯ メニュー経由、MC の入り切り・曲の編集は行 ⋯ メニュー経由に変更。スクリプト `ui-workbench/wo/update_tests.py` に記録
5. **実装中に見つけて直した不具合2件**: ①下部固定バーがページ末尾のバックアップボタンを覆っていた(押せない)→ `body.with-bottom-bar` で余白 ②⋯ メニューから共有を開くと、閉じたダイアログ内にフォーカスが残り `clipboard.writeText()` が解決しなくなる → 閉じたら ⋯ ボタンへフォーカスを戻す
6. **§6 の未回答**: 上部タブ6個は「触らない」で発注者確認済み。他4件(持ち時間入力の置き場・バックアップ・エナジー select・エナジー度ドット)は Claude 推奨(A案)のまま実装済み
