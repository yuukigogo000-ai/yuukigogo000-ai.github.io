## 0. 目的(1〜2行)

例: セトリ編集画面の主操作を1つに絞り、見本Aのトークンに揃えて「同じ重さのボタンが8個並ぶ」状態を解消する。

## 2. 交通整理(**あなたが記入**・空なら着手しない)

| 問い | 答え |
|---|---|
| この画面の**主操作は1つだけ**、何? | 例: 「曲を追加する」 |
| 上位3タスク(頻度順) | 例: ①曲を並べ替える ②持ち時間の残りを見る ③共有する |
| 格下げ/隠すもの | 例: 複製・名前変更・削除はメニュー(…)へ。印刷は共有の中へ |

| 状態の再現フック | 例: `?state=empty` `?state=long`(無ければ本WOで追加。本番は無視される実装) |
| 使う場面 | 例: スタジオで片手・暗い所・立ったまま |

## 7. 手順

1. G0: 基準線が最新か確認(古ければ取り直し)
2. G3: トークン抽出 → `:root` へ(既存変数と衝突すれば対応表を §4 に追記)
3. G4: 実装(見た目のみ。JS はクラス付け替え・状態フック追加まで)
4. G5: `uicheck --baseline` GREEN / 既存テスト緑
5. G6: 横並び画像(見本 | 実装)を同条件で作り、あなたに3問
6. NG → 差分を §5 に追記して 3 へ
7. G7: 実機確認(セトリズムは必須)
8. G8: 完了報告(§11)

## 8. 実装メモ(スマホWebの約束事)

Safe Area / `viewport-fit=cover` / 主操作は下部 / hover 前提禁止 / `inputmode` / 入力16px以上 / `100vh` 禁止 / system-ui 系フォント / ダーク両対応 / rem・em で拡大追従。詳細 PLAYBOOK §5。
