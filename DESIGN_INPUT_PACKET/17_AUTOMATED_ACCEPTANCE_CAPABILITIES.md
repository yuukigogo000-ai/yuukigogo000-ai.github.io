次工程で Design Package を忠実実装したことを機械的に確認できる項目を、
**このリポジトリで実際に可能な範囲**に限って分類した。

前提: リポジトリにテストコードは存在しない(C-03)。したがって以下はすべて**新規に用意する検証**であり、
既存テストの再利用ではない。検証コードは製品コードを変更せずに外部から実行できる。

## AUTOMATABLE (20件)

| 検証項目 | 方法 |
|---|---|
| 対象幅でのページ水平オーバーフロー=0 | ヘッドレスブラウザで幅を設定し scrollWidth>clientWidth を判定 |
| タップ領域の実寸(最小サイズ) | getBoundingClientRectで全操作要素の幅高を測定 |
| コンソールエラー / 未捕捉例外 = 0 | pageerror と console(type=error) を収集 |
| 壊れたリソース参照 = 0 | requestfailed の監視。ただし本製品は実行時リクエスト0が正常(P-27) |
| 実行時の外部リクエスト = 0 の維持 | ネットワーク監視で外部ホストへの要求が発生しないことを確認 |
| 全機能(FN-01〜FN-39)の存在と到達 | DOM操作で各エントリポイントを実行し、状態変化を検証(FUNCTION_INVENTORYのENTRY_POINT列を使用) |
| 画面キャプチャの取得 | 各SCREEN_IDに対応する状態を作ってスクリーンショット |
| DOM識別子(70件)の保持 | P-30のID一覧が全て存在することを照合 |
| グローバル公開3件の保持 | window.closeModal/doReset/startGame の型を検査 |
| localStorageの保存と復元 | 1営業日実行→リロード→state一致を検証 |
| セーブのサニタイズ(改竄耐性) | 不正セーブを投入してリロードし、例外なし・値が範囲内であることを検証 |
| ゲームロジックの回帰 | simulateDay()を直接反復し、クリア日数・倒産率の分布が基準内であることを検証 |
| 倒産後の操作封鎖(P-03) | money<0を作り、売却・営業・各施策が状態を変えないことを検証 |
| 破壊的操作の確認(P-04) | dialogイベントの発生を検証 |
| prefers-reduced-motion での動作 | エミュレーションを有効化して、動作と操作可能性を検証 |
| 必須コピー(EXACT 13件)の保持 | 文字列の存在をDOMまたはソースで照合 |
| アセットの実在と寸法 | ファイル存在とPNGヘッダの寸法を照合 |
| PWAマニフェストとSWの整合 | manifestのicons参照先の実在、PRECACHE対象の実在を照合 |
| Electron起動と描画 | 仮想ディスプレイでElectronを起動し、描画と1営業日実行を検証 |
| オフライン起動 | SW登録後にオフライン化してリロードし、起動を検証 |

## PARTIALLY_AUTOMATABLE (3件)

| 検証項目 | 方法 |
|---|---|
| テキストのクリッピング/はみ出し | 要素のscrollWidth/offsetWidth比較で検出可。視覚的な詰まりは目視 |
| 全状態(ST-01〜ST-62)の到達 | stateを直接組み立てて到達可。ただしST-50/57/58等の抽選依存はMath.randomの差し替えが必要 |
| アニメーションのFPS/ジャンク | トレース取得は可能だが、体感の滑らかさの判定は目視 |

## VISUAL_REVIEW_REQUIRED (3件)

| 検証項目 | 方法 |
|---|---|
| 配色・階層・世界観の意図適合 | Design Authorityによる目視レビュー |
| 俯瞰表現が経営状態を伝えているか | 同上 |
| 装飾密度のBRAND/TASK区分の妥当性 | 同上 |

## 自動検証を成立させている実装上の足場

| 足場 | 内容 | 根拠 |
|---|---|---|
| DOM識別子 | 静的40件 / 動的含め70件のid属性 | P-30 |
| グローバル公開 | `window.closeModal` / `doReset` / `startGame` | P-29 |
| ロジックの直接呼出 | `simulateDay()` `newGame()` `totalAssets()` 等がグローバルスコープ | pachinko/index.html:718,629,676 |
| 状態の単一化 | グローバル変数 `state` を直接組み立て可能 | pachinko/index.html:627 |
| 保存の単一キー | localStorage 1キーの投入で任意局面を再現可能 | P-24 |

**注意**: これらは検証を可能にしている足場であり、UI再設計で削除・改名してはならない(P-29, P-30)。

## 自動化できないこと(明示)

- 配色・書体・階層・世界観がデザイン意図に合致しているかの判断
- 俯瞰表現が経営状態を伝えられているかの判断
- 装飾密度が BRAND_CRITICAL / TASK_CRITICAL の区分に適合しているかの判断
- 体感的な滑らかさ(FPSの数値は取得できるが、良否の判断は目視)
