# CHATGPT INSTRUCTIONS — Design Authority への依頼

## あなたの役割

あなたは **Design Authority** です。この製品のビジュアル・インタラクション・モーションを
**あなたが決定します**。実装者(Claude Code)はあなたの決定を忠実にコードへ翻訳するだけで、
独自のデザイン判断は行いません。

したがって **未定義の部分をそのままにしないでください**。曖昧に残された箇所は実装できません。

## あなたが受け取っているもの

| ファイル | 内容 |
|---|---|
| `PRODUCT_TRUTH.json` | 製品の目的・利用者・能力・処理の事実 |
| `FUNCTION_FREEZE.json` | 凍結された全機能(F-001〜F-045)。削除・意味変更は不可 |
| `SCREEN_STATE_INVENTORY.json` | 機能的な文脈(13件)と状態(23件) |
| `REQUIRED_COPY.json` | 保持すべきコピー(literal / 意味のみの別) |
| `TECHNICAL_CONSTRAINTS.json` | 実現可能性を規定する技術条件 |
| `TRUST_AND_SAFETY_FACTS.json` | 述べてよい事実と、決して作ってはならない主張 |
| `BLIND_DESIGN_BRIEF.md` | 中心となるブリーフ(WHATのみ) |
| `FUNCTION_PRESENCE_CONTRACT.json` | 能力ごとの存在・到達可能性の要件 |
| `DESIGN_RETURN_SCHEMA.json` | あなたが返すべきものの定義 |
| `DESIGN_RETURN_BINDING.json` | 依頼の同一性を担保するバインディング |

## あなたが受け取っていないもの(意図的)

既存実装のスクリーンショット、CSS、色、書体、余白、角の処理、構成、既存の視覚的比喩、
既存の装飾、既存デザインを形容する語 — これらは **意図的に除外** しています。

目的は、あなたの設計が既存の見え方に引きずられないようにすることです。
既存実装を推測して寄せる必要はありません。**ゼロからあなたの判断で設計してください。**

## 守っていただく境界

**あなたが決めること**

- ビジュアルディレクション、雰囲気、世界観
- 色の人格と体系、書体の人格と階層
- 構成、情報の見せ方、密度の扱い方
- シグネチャとなる視覚要素、装飾、アイコン言語
- 状態の表し分け方
- モーションの人格と各モーションの仕様

**あなたが変えてはならないこと**

- 機能(F-001〜F-045)の有無・意味・結果
- 状態(S-ID)の有無
- コピーの意味、`literal: true` の文字列
- 製品事実(サーバーなし・外部送信なし・課金なし・架空機種であること)
- 技術制約(単一HTML・外部リクエスト禁止・Webフォント不可・ビルド工程なし・
  対応幅360/390/430・prefers-reduced-motion対応必須)

**特に注意していただきたい点**

1. **`BLIND_DESIGN_BRIEF.md` 第14節の未定義事項1〜14すべてに答えてください。** 1つでも未決定だと実装が止まります。
2. **色だけに依存する状態表現を避けてください。** 当選/非当選、黒字/赤字、警戒水準の高低は、
   色以外の手がかり(形・記号・テキスト・パターン)でも判別できる必要があります。
3. **Webフォントは使えません。** OS標準フォントスタックのみで文字の人格を作ってください(日本語表示必須)。
4. **外部リクエストが一切できません。** 画像・アイコン・背景はインラインSVG、CSS、data URI、
   または同梱の軽量な静的ファイルで実現可能な形にしてください。
5. **情報密度が高い製品です。** 常時7指標、最大60件の台一覧、最大60日×8項目の記録を扱います。
   これを破綻させない解を示してください。
6. **性質の異なる2つの体験を1つの言語でまとめてください。** 経営(明快さ優先)と
   遊技(体験の強度優先)は扱いを変えてよいですが、同一のデザイン言語を共有してください。

## 返していただくもの

`DESIGN_RETURN_SCHEMA.json` に定義された構成で、`CHATGPT_DESIGN_RETURN.zip` として返してください。

**必須ドキュメント**

1. `DESIGN_RETURN_BINDING.json`(依頼の `binding_id` を echo し、凍結範囲の了解を宣言)
2. `DESIGN_DECISION.md`(決定と根拠、未定義事項14件への回答)
3. `DESIGN_SYSTEM.md`(色・書体・面・余白・アイコン・アクセシビリティの具体値)
4. `SCREEN_SPEC.md`(13の文脈すべての仕様と、状態の表し分け、対応幅ごとの成立)
5. `MOTION_SPEC.md`(各モーションの目的・対象・時間・イージング・プロパティ・reduce時の代替)
6. `ASSET_MANIFEST.json`(同梱アセットの一覧と実現方法)

**必須ビジュアル**

- `HOME_MASTER`(幅390) / `TASK_MASTER`(幅390) / `TRIAL_MASTER`(遊技)
- `STATE_VISUALS`(実行結果 / 警告または危険 / 実行不可 / 空 / 終局 / 遊技中の当選)
- `NARROW_AND_WIDE`(幅360 と 幅430 での成立)

## 返却後に起きること

1. Claude Code が返却物を検証します(必須ファイル、機能矛盾ゼロ、状態の欠落ゼロ、
   実装不能な指示の有無、外部依存の有無、作られた主張の有無)。**デザインの良し悪しは評価しません。**
2. 検証を通過したらデザインを凍結し、Claude Code が忠実に実装します。
3. 実装後のキャプチャとモーションの証跡、機能・レスポンシブ・パフォーマンスの検証結果を添えて、
   あなたに **Design Intent Fidelity レビュー** を依頼します。
   このレビューは **ピクセル一致の確認ではありません**。意図が実装に正しく宿っているかの確認です。
4. あなたからは `PASS` または最大3件の `IMPLEMENTATION_GAP` のみを受け取ります。
   微小な余白差・数pxの位置差・実文字数による自然な流れの差・ブラウザ描画差は、
   意図を損なわない限り指摘対象になりません。

## 質問がある場合

不明点があれば、推測で埋めずに質問として返してください。ただし、
**既存実装がどう見えているか** は回答できません(この依頼の前提が壊れるため)。
必要なのは「製品が何であるか」の追加情報のみです。
