# ASSUMPTIONS — UI REDESIGN PIPELINE v4.0

Human Contact Gate 以外での人間への照会は行わないため、判断が必要だった点を自己解決し記録する。

## A-01: 再設計の対象アプリ

- **判断**: 対象は `pachinko/index.html`(パチスロ帝国)とする。
- **根拠**: 本セッションで一貫して開発・検証してきた稼働中のアプリであり、
  `pachinko/DESIGN.md` に設計・検証記録が蓄積されている唯一のアプリケーションである。
- **除外**: リポジトリ直下の `index.html`(JAN→楽天価格取得ツール)は、本セッションの作業対象外であり、
  機能・利用者・目的がまったく異なるため対象に含めない。パイプラインを再実行すれば同手順で対応可能。

## A-02: 現行アイコン資産の扱い

- **判断**: `pachinko/icon-192.png` / `icon-512.png` を PRODUCT_ASSET_FIXED として
  Design Request に**含めない**。
- **根拠**: これらはブランド由来の固定資産ではなく、本セッションで生成した現行ビジュアルの派生物である。
  同梱すると現行のビジュアルアンカーを Design Authority へ渡すことになり、Phase 2 の
  Visual Sanitization に反する。
- **代替**: ファイルパスと寸法(192/512)およびテーマ色値が必要であるという**技術的事実**のみを
  `TECHNICAL_CONSTRAINTS.json` に記載し、絵柄と色の決定は Design Authority へ差し戻した。

## A-03: 「Home」の定義

- **判断**: 本アプリにはランディングページが存在しないため、
  `FUNCTION_PRESENCE_CONTRACT.json` における HOME を
  「オンボーディング完了後に利用者が最初に置かれる文脈」と定義した。
- **根拠**: 単一ドキュメント構成でURLルーティングを持たないため、物理的なHome画面は存在しない。
  存在要件を定義するには機能的な定義が必要だった。

## A-04: 現行の絵文字ラベルの扱い

- **判断**: `REQUIRED_COPY.json` では絵文字を除いた本文のみを記載し、
  アイコン言語(絵文字の採否を含む)を Design Decision として差し戻した。
- **根拠**: アイコン言語は Master Prompt 上、明確に Design Authority の領域である。
  絵文字を必須コピーとして渡すと視覚言語を先取りして指定することになる。
- **例外**: 130件のイベント文・機種名・実績名は製品コンテンツであるため意味・文字列を保持対象とした。

## A-05: 帳簿の推移表現に関する既存コピー

- **判断**: 黒字/赤字の判別方法を説明するコピー(C-111)は `presentation_dependent: true` とし、
  Design Authority が採用する表現方式に合わせて文言を書き換えてよいものとした。
- **根拠**: このコピーは表現方式そのものを説明するものであり、意味(黒字と赤字が色のみに依存せず
  判別できること)を保持すれば文言は表現方式に従属する。意味自体はアクセシビリティ要件として
  ブリーフに明記済み。

## A-06: 130件のイベント文の同梱方法

- **判断**: 全文ではなく、件数・文字数統計・代表10件・出現条件を `REQUIRED_COPY.json` に記載した。
- **根拠**: 全文はアプリ内に定義済みで Design Authority が新規作成する必要がない。
  設計判断に必要なのは「その分量と最大長を収容できること」という制約であり、
  全文の同梱は Design Request の焦点をぼかす。意味の保持義務は Function Freeze 側で担保している。

## A-07: Design Request の受け渡し方法

- **判断**: 自動ブリッジ(ChatGPTへの自動送信・受信 inbox)はこのセッション環境に存在しないため、
  Gate H3(AWAITING_CHATGPT_DESIGN)へ到達させる。
- **根拠**: 利用可能な接続はGitHub関連と Google Drive(未認証・このセッションでは認可不可)のみで、
  Design Authority へ渡す自動経路が存在しない。物理的な受け渡し操作が必要。

## A-08: 成果物のコミットとプッシュ

- **判断**: 生成物をブランチ `claude/pachinko-slot-management-app-p2j058` にコミット・プッシュした。
- **根拠**: 本実行環境のコンテナは一定時間で回収されるため、プッシュしない成果物は失われる。
  対象は production ではない作業ブランチであり、公開ページ(main)への反映・マージ・デプロイは行っていない。
  ゲーム本体のコードは一切変更していない(追加されたのはドキュメントのみ)。
  Gate H2 が対象とする不可逆・production 影響のある操作には該当しないと判断した。

## A-09: Phase 5 以降の進行

- **判断**: Phase 5(Design Return Verify)以降は Design Authority からの返却物が存在しないと
  開始できないため、Phase 4 完了 + 自己検証 PASS の時点で Gate H3 に到達させる。
- **根拠**: Claude Code は Design Authority ではないため、返却物を自ら生成して代替することは
  Master Prompt 第0節の役割分離に違反する。
